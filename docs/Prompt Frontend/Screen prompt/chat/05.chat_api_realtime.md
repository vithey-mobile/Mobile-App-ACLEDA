# 05 — Chat API, WebSocket STOMP & Firebase Push

Backend-ready contract for REST, real-time, and push notifications.

## Platform architecture

```text
Flutter App
    │
    ├── Dio (REST) ──────────► API Gateway :8080 ──► chat-service :8087
    │                              │
    │                              ├── PostgreSQL (messages, conversations)
    │                              └── Redis (presence, typing, message cache)
    │
    ├── web_socket_channel (STOMP) ► Gateway /ws ──► chat-service STOMP broker
    │
    ├── Isar (local cache)
    │
    └── firebase_messaging ◄──── notification-service ◄── RabbitMQ chat.message.sent
```

## REST API (canonical Vithey paths)

Base: `API_BASE_URL` (Flutter constants **omit** `/api/v1` prefix — gateway adds it).

### Conversations (= your `GET /chats`)

| Method | Flutter constant | Path |
|--------|------------------|------|
| GET | `ApiEndpoints.conversations` | `/conversations?page=1&limit=20` |
| POST | — | `/conversations/request` |
| POST | `conversationAccept(id)` | `/conversations/{id}/accept` |
| POST | `conversationDecline(id)` | `/conversations/{id}/decline` |
| POST | `conversationBlock(id)` | `/conversations/{id}/block` |

### Messages (= your `GET /messages/{conversationId}`)

| Method | Path | Body |
|--------|------|------|
| GET | `/conversations/{id}/messages?page=&limit=` | — |
| POST | `/conversations/{id}/messages` | `{ text, client_message_id, reply_to_message_id? }` |
| PATCH | `/messages/{message_id}/read` | — |

### Read batch

```json
POST /conversations/{id}/messages/read
{ "message_ids": ["uuid", "uuid"] }
```

Single-message read: `PATCH /messages/{id}/read`. Use batch when marking thread as read.

## WebSocket STOMP

Vithey uses **one user queue**, not per-room URLs.

| Item | Value |
|------|-------|
| URL | `wss://{API_HOST}/ws` (or `ws://` dev) |
| Protocol | STOMP 1.2 over `web_socket_channel` |
| Connect headers | `Authorization: Bearer {jwt}` |
| Subscribe | `/user/queue/messages` |
| Send destination | `/app/chat.send` |
| Typing | `/app/chat.typing` |
| Presence | `/user/queue/presence` |
| Heartbeat | `/app/chat.heartbeat` (refresh online status) |

### Your `ws://server/chat/{conversationId}` mapping

Flutter **filters** frames by `conversation_id` in JSON body. Optional future:

```text
SUBSCRIBE /topic/conversation.{conversationId}
```

Implement only when chat-service documents it. Until then use user queue.

## `ChatStompService` (Flutter)

```dart
class ChatStompService {
  Stream<ChatStompPayload> get messages;
  Stream<TypingPayload> get typing;
  Stream<ConnectionState> get connectionState;

  Future<void> connect({required String jwt});
  Future<void> disconnect();
  Future<void> sendMessage({
    required String conversationId,
    required String text,
    required String clientMessageId,
    String? replyToMessageId,
  });
  Future<void> sendTyping({required String conversationId, required bool isTyping});
}
```

Use package `stomp_dart_client` **or** manual STOMP framing over `WebSocketChannel.connect(Uri.parse(wsUrl))`.

Recommended: `stomp_dart_client: ^2.0.0` wrapping `web_socket_channel`.

## Firebase Cloud Messaging

### Registration flow

```text
1. App start → Firebase.initializeApp()
2. Request notification permission (iOS)
3. FCM.getToken() → POST /users/me/fcm-token (user-profile or notification-service)
4. OnTokenRefresh → update server
```

### Incoming message (background)

`lib/data/push/fcm_service.dart`:

```dart
@pragma('vm:entry-point')
Future<void> firebaseMessagingBackgroundHandler(RemoteMessage message) async {
  await Firebase.initializeApp();
  // Show local notification via flutter_local_notifications
}

void setupFcm() {
  FirebaseMessaging.onMessage.listen(_showForegroundNotification);
  FirebaseMessaging.onMessageOpenedApp.listen(_openChatFromPush);
  FirebaseMessaging.instance.getInitialMessage().then(_openChatFromPush);
}
```

### Notification payload (from notification-service)

```json
{
  "notification": {
    "title": "Kimheang",
    "body": "See you tomorrow"
  },
  "data": {
    "type": "chat.message",
    "conversation_id": "uuid",
    "message_id": "uuid",
    "sender_id": "uuid"
  }
}
```

### Deep link routing (`notification_router.dart`)

```dart
void openChatFromPush(Map<String, dynamic> data) {
  final conversationId = data['conversation_id'] as String?;
  if (conversationId == null) return;
  Get.toNamed(AppRoutes.chatDetail, arguments: ChatDetailArgs(conversationId: conversationId));
}
```

### Foreground behavior

- If `ChatDetailController` already showing same `conversationId` → **no** heads-up notification; update thread only
- Else → `flutter_local_notifications` banner; tap opens thread

## Error mapping

| HTTP | Code | Flutter UX |
|------|------|------------|
| 401 | `UNAUTHORIZED` | Refresh token or login |
| 403 | `FORBIDDEN` | "You can't message this user" |
| 404 | `NOT_FOUND` | Remove conversation from list |
| 409 | `CONFLICT` | Reconcile duplicate request |
| 422 | `BUSINESS_RULE_VIOLATION` | Self-message / invalid state |

## `ChatRepository` contract (complete)

```dart
abstract class ChatRepositoryContract {
  Stream<List<ConversationModel>> watchConversations();
  Stream<List<ChatMessage>> watchMessages(String conversationId);

  Future<void> syncConversations();
  Future<void> syncMessages(String conversationId, {int page = 1});
  Future<List<MessageRequestModel>> fetchMessageRequests();

  Future<ChatMessage> sendMessage({
    required String conversationId,
    required String text,
    String? replyToMessageId,
  });

  Future<void> markMessageRead(String messageId);
  Future<void> deleteMessage(String messageId); // feature-gate
  Future<void> acceptRequest(String conversationId);
  Future<void> declineRequest(String conversationId);
  Future<void> blockConversation(String conversationId);

  void connectRealtime();
  void disconnectRealtime();
}
```
