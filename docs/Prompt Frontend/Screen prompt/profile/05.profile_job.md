## Usage model (Poster / Applier)

There is **no role picker**. Everyone sees the same Profile shell. Usage shapes the data:

| Label in prompts | Meaning | Jobs tab |
|------------------|---------|----------|
| **Poster (HR)** | User who posts jobs | Own JOB posts + applicant tools |
| **Applier (Student)** | User who applies | Usually empty (**No job posts yet**) |

- Do **not** use real person names in prompts — say **Poster** / **Applier** (or HR / Student).
- Mock demo: logged-in session = **Poster**; a separate fixture user = **Applier** (appears in Application List, has no JOB posts).
- Same UI for both; never gate the Jobs tab by a stored role. Empty states are valid.
- Own job → never **Apply**; show Application List / counts. Visitor → Apply / Applied / Closed.

## Goal

List the user's JOB posts as compact cards matching the reference. Split taps so poster image, job info, and the ⋮ menu do different things. Use **20px** horizontal screen padding. Mock posters may be non-English — use **English mock job copy** with the provided image assets.

## Card spec (`profile_job_card.dart`)

| Zone | Spec |
|------|------|
| Thumbnail | ~72×72dp square, left, rounded 8dp — **local asset or network** |
| Title | Bold — job title |
| Subtitle | Company + `( Full-time )` style employment type — muted |
| Location | Pin icon + address |
| Time | Relative under the **poster image**: `N hours ago` / `N days ago` / `N months ago` / `N years ago` |
| Overflow | **⋮** top-right (own profile) |
| Footer left | Teal pill **{n} Application** |
| Footer right | **View List >** |
| Card | Rounded 12dp, border; list horizontal padding **20px** |

## Interaction (from `update.md`)

| Tap target | Result |
|------------|--------|
| **Poster image** | Open **fullscreen** poster viewer (no outer padding/margin). Poster image **centered** in the middle; job info **floats from the bottom** over a dark gradient (title, company/type, location, posted time). Do not open Application List. |
| **Job information / content** (title, company, location, time, footer text areas that mean “open list”) | Navigate to **Application List** (`JobApplicantsArgs`) |
| **View List >** / Application badge | Same as content → Application List |
| **⋮** | Show **Edit / Delete** menu (own only) |

Keep image preview and Application List as **two separate** interactions. Never open image preview when the content area is tapped.

## Visitor

| State | UI |
|-------|-----|
| Not applied, open | **Apply** → apply CV flow |
| Applied | **Applied** |
| Closed | **Closed** — disabled |
| ⋮ | Hidden |
| Image tap | Still opens image preview |
| Content tap | Post detail and/or Apply (do not expose owner Application List / counts) |
