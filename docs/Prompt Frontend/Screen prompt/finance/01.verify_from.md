## Goal

Collect student ID, email, optional password field (UI only — see credential rule), and student document; submit once; route by authoritative status. **UI-only redesign** — do not change controllers/services/repositories behavior beyond wiring new widgets.

## Critical credential rule (unchanged)

The mock shows a **Password** field. The current verification API still expects only `student_id` + `university_email` (+ document when enabled).

- Show the Password field to **match the mock**.
- Do **not** send password to `/students/verify` or any verification payload.
- Do not store, log, or attach password to verification drafts.
- Prefer obscure text + visibility toggle for the field.
- If product later adds Vithey reauthentication, label it clearly; never pretend this is a university login.

## Current validation (dev — preserve until product changes)

Match the app’s current behavior unless product updates it:

- Student ID: required (existing rules).
- Student Email: required non-empty — **no format/domain check yet** (dev agreement).
- Document: keep current required/optional behavior of the live form.
- Password: not validated for API; optional for UI.

### 4. Upload Student Document — two UI states

- Copy:
  - **Drag & drop your file here**
  - or tap to browse

- Tap → existing file picker (preserve MIME/size rules when enforced)

## Light / dark mode

- AppBar, fields, dashed upload, preview row, CTA, info card all use theme tokens (`AppSemanticColors` / `ColorScheme`).
- Upload icon asset: ensure contrast on dark sheet (or provide theme-aware wrapper).
- Avoid hardcoded white-only backgrounds for the page body.

## Submission / security / navigation

Unchanged unless noted:

- State machine: `editing → validating → uploadingDocument? → submittingVerification → pending|verified|rejected|error`
- No password in API payload
- Private document handling rules when uploads are enabled
- Route:
  - Pending → verification status
  - Verified → status or Finance
  - Already pending → status
  - Back → previous safe screen without submit
- Profile **Verify student** opens this form; Finance nav gate unchanged (`FinanceNavigation`)
