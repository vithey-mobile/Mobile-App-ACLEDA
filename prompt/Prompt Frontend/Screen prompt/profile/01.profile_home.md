# 01 — Profile Home Shell (Owner / Visitor)

Build the shared **Profile shell** from:

- `Own Profile (Home).png` / `Own Profile (About).png` — authenticated user
- `View Profile (About).png` — another user's profile

> As-built cover + tabs: root [`update.md`](update.md).  
> **Active cover widget:** `ProfileCoverRedesign` (`profile_cover_redesign.dart`). `ProfileWavyHeader` is retained as backup only.  
> Tab bodies: About `02.profile.about.md`; Edit `07.profile_edit_info.md`; others in sibling prompts (`03`-`06`, `poster_job/`).

## Route

| Field | Value |
|-------|-------|
| Route | `AppRoutes.profile` with `ProfileArgs(userId)` |
| Module | `lib/modules/profile/` |
| Entry | Bottom nav Profile tab, avatar taps, notifications |
| Prompt | `Screen prompt/profile/01.profile_home.md` |

Compute `isOwnProfile = targetUserId == authSession.userId`. Never trust a caller-supplied owner flag.

## Usage model (Poster / Applier)

There is **no role chooser** at signup. Profile chrome is identical for everyone; **Jobs** vs **Applied Jobs** content follows how the account is used:

| Prompt label | Usage | Typical Profile |
|--------------|--------|-----------------|
| **Poster (HR)** | Posts jobs, reviews applicants | Jobs filled; Applied Jobs often empty |
| **Applier (Student)** | Applies with CV | Applied Jobs filled (own only); Jobs often empty |

- Prompts must say **Poster** / **Applier** (or HR / Student) — **not** real display names.
- Do not hide tabs by role. Actions still follow ownership (`isOwnProfile`, own job vs visitor).
- Mock: logged-in user demonstrates **Poster**; another fixture user demonstrates **Applier**.

## Wavy cover header (`profile_wavy_header.dart`)

| Spec | Value |
|------|-------|
| Height | ~168dp |
| Background | Soft teal **theme-aware**: `Color.alphaBlend(authHeaderTeal @ ~55% light / ~38% dark, scaffoldBackground)` — do **not** hardcode `#7DDAD6` |
| Bottom edge | Wavy / organic curve via `ProfileWavyClipper` (`ClipPath`) |
| Decor icons | `</>`, dice, cube, chat, star, sparkle — slightly darker/stronger than cover (blend black/white over cover) |
| Cover chrome | Settings / CV icons contrast cover via luminance (not fixed white) |
| Own chrome | Settings gear top-left → `AppRoutes.settings`; optional CV preview icon top-right → preview own CV |
| Visitor | No settings / CV chrome on cover |

Do not use a flat rectangular banner — match the curved transition in reference images.

Name + bio sit under the cover (same widget), **20px** horizontal padding. Use `appColors.heading` / `appColors.muted` (light/dark).

## Avatar (inside `profile_wavy_header.dart`)

| Spec | Value |
|------|-------|
| Size | Radius **56** → **112dp** diameter (larger than v0) |
| Position | Centered, overlapping cover bottom |
| Border | ~4dp ring = **scaffold background** (adapts light/dark) + `appColors.subtleShadow` |
| Source | `avatarUrl` or initials via `UserAvatar` |

## Stats row (`ProfileStats` in `profile_header.dart`)

Three equal columns — reference shows **Likes**, not post count:

| Column | Field | Format |
|--------|-------|--------|
| Likes | `likeCount` | `128K`, `10K` via `formatProfileCount` |
| Followers | `followerCount` | `40K`, `8K` |
| Following | `followingCount` | `3.8K`, `1K` |

- Number: bold ~17sp — `appColors.heading`
- Label: muted 12sp below number — `appColors.muted`
- Padding: `EdgeInsets.fromLTRB(20, 14, 20, 10)`

## Bio

- Centered under the name
- Max **2 lines**, ellipsis overflow (not expandable)
- `appColors.muted` (light/dark)
- Never render as HTML

## Action row (`ProfileActionRow` in `profile_header.dart`)

General:

- Compact height **40**, radius **10**, ~13sp labels
- Tighter spacing; **20px** horizontal padding
- **Edit** and **Verify** are identical controls except fill/foreground color: both `FilledButton.icon` (leading icon + text), **equal width** (`Expanded` 1:1)
- Share stays icon-only (unchanged)
- Use `colorScheme.primary` / `onPrimary` (not hardcoded `AppColors.primary` / white) so dark mode primary matches theme

### Own profile (`isOwnProfile == true`)

| Button | Style | Action |
|--------|-------|--------|
| **Edit Profile Info** | `colorScheme.primary` fill, `onPrimary` icon + text (`edit_outlined`) | `openEditProfile()` → `AppRoutes.editProfile` |
| **Verify Student** / **Review Verify** | **Same size, padding, radius, icon+text layout as Edit**; fill `appColors.inputFill` (not fixed `#EEEEEE`), `appColors.heading` icon + text (`verified_user_outlined` / `verified_outlined` when reviewing) | Label from `StudentVerificationRepository.isVerified`: not verified → form (`AppRoutes.studentVerification`); verified → status (`AppRoutes.verificationStatus`) via `openVerifyStudent()` |
| **Share** | **Icon only** (`Icons.ios_share`) — no border, no filled background; `colorScheme.primary` | `shareProfile()` native share |

Never show **Follow** or **Message** on own profile.

> **`update.md`:** Verify uses the exact same button style as Edit; change only the color. Share remains icon-only.

### Visitor profile

| Button | Style | Action |
|--------|-------|--------|
| **Follow** / **Following** | Primary teal when not following; outlined when following | `toggleFollow()` optimistic |
| **Message** | Outlined | `startMessage()` → chat or request composer |
| **Share** | Icon-only (same v1 treatment) | Share profile link |

Apply the same compact size/spacing as the owner row.

## Bottom navigation

- Reuse `HomeBottomNavigation` with `currentIndex: 4` (Profile active)
- Center FAB (+) for Create Post
- Profile tab: teal icon + light teal pill background

## Follow behavior

- Optimistic POST follow / DELETE unfollow
- Rollback on failure
- Sync count across Home and Profile caches
- Server rejects self-follow; UI never shows it

## Message behavior

- Existing ACTIVE conversation → `ChatDetail`
- PENDING request → request state UI
- No conversation → explicit composer → `POST /conversations/request`
- Never auto-send default first message

## API contract (aggregate profile)

> Full API: `Prompt Backend/services/user-profile-service/`
**Profile header** — `GET /api/v1/users/me` (own) or `GET /api/v1/users/{userId}` (visitor):

`json
{
  "user_id": "uuid",
  "full_name": "Display Name",
  "bio": "...",
  "avatar_url": "..."
}
`

**Stats row** — from **content-service** (not profile PATCH): likes, followers, following counts via separate calls or enriched DTO when content API provides it.

**Avatar update** — `POST /files/upload` (AVATAR) + `PATCH /users/me/avatar` (own only).

Do not expect `cover_url`, `stats`, or `is_following` on user-profile-service responses today.
