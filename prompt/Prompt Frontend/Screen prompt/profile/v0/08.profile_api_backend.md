# 08 — Profile API & Backend Contract

Backend-ready contract for **profile read/update**, **avatar**, and **settings**.  
Source of truth for Flutter `ProfileRepository` — **no Flutter code in this file**.

> **Service:** `user-profile-service` (port `8082`, Eureka `user-profile-service`)  
> **Gateway:** `http://localhost:8080/api/v1` — generic `/users/**` routes here except CV and social paths (see below).

## Architecture

```text
Flutter App
    │
    ├── Dio REST ──► API Gateway :8080 ──► user-profile-service :8082
    │                      │
    │                      ├── PostgreSQL user_db (profiles, user_settings)
    │                      └── OpenFeign ──► file-service (avatar file validation)
    │
    ├── content-service ──► posts, likes, followers (profile tabs — not profile-service)
    ├── career-service ──► GET/PUT /users/me/cv (gateway route 0)
    └── auth-service ──► login, email/password (NOT profile update)
```

## Gateway routing (important)

| Order | Path | Target |
|-------|------|--------|
| 0 | `/api/v1/users/me/cv`, `/users/me/cv/**` | `career-service` |
| 0 | `/api/v1/users/*/follow`, `*/followers`, `*/following`, `*/posts` | `content-service` |
| 1 | `/api/v1/users/**` | `user-profile-service` |

## Endpoints (canonical)

Base: `API_BASE_URL` (Flutter constants **omit** `/api/v1` — gateway adds it).

| Method | Flutter constant | Path | Purpose |
|--------|------------------|------|---------|
| GET | `usersMe` | `/users/me` | Own profile + language/theme summary |
| GET | `userById(id)` | `/users/{user_id}` | Public profile (visitor view) |
| PATCH | `usersMe` | `/users/me` | Update profile text fields |
| PATCH | `userAvatar` | `/users/me/avatar` | Set avatar after file upload |
| GET | `userSettings` | `/users/me/settings` | App settings |
| PATCH | `userSettings` | `/users/me/settings` | Update settings / FCM token |
| GET | `usersSearch` | `/users/search?search=&page=&limit=` | People search (chat, mentions) |

**Not in user-profile-service:**

| Need | Service | Path |
|------|---------|------|
| Email / password | auth-service | `/auth/*` |
| Saved CV | career-service | `/users/me/cv` |
| Posts, jobs tab content | content-service | `/users/{id}/posts`, `/posts` |
| Followers / likes counts | content-service | follow + reaction APIs |

## GET `/users/me` — own profile

Returns `MeProfileResponse` (profile fields + `language` + `theme`).

```json
{
  "data": {
    "user_id": "uuid",
    "full_name": "Khorn Molika",
    "bio": "Main character of my life...",
    "avatar_url": "https://minio/avatars/...",
    "telegram_link": "https://t.me/khorn",
    "facebook_link": "https://facebook.com/khorn",
    "university": "ACLEDA University of Business",
    "major": "Computer Science",
    "graduation_year": 2026,
    "language": "en",
    "theme": "system"
  }
}
```

Use on: Profile shell (own), Edit screen prefill, startup session hydrate.

## GET `/users/{user_id}` — public profile

Returns `ProfileResponse` — **same profile fields, no settings, no email/phone**.

```json
{
  "data": {
    "user_id": "uuid",
    "full_name": "Heng Liza",
    "bio": "...",
    "avatar_url": "https://...",
    "telegram_link": "https://t.me/...",
    "facebook_link": "https://facebook.com/...",
    "university": "AUB",
    "major": "IT",
    "graduation_year": 2025
  }
}
```

Rules:

- Never expect `email` or `phone` from this endpoint (credentials live in auth-service; not exposed here).
- Visitor About tab renders only fields returned above.

## PATCH `/users/me` — update profile

**Partial update:** send only changed fields; `null` / omitted keys are **not** cleared server-side.

### Request body (all optional)

```json
{
  "full_name": "Khorn Molika",
  "bio": "Main character of my life...",
  "telegram_link": "https://t.me/khorn",
  "facebook_link": "https://facebook.com/khorn",
  "university": "ACLEDA University of Business",
  "major": "Computer Science",
  "graduation_year": 2026
}
```

### Validation (server)

| Field | Rule |
|-------|------|
| `full_name` | max 160 chars |
| `bio` | max 2000 chars |
| `telegram_link`, `facebook_link` | max 500 chars each |
| `university`, `major` | max 160 chars each |
| `graduation_year` | integer 1900–2100 |

### Response `200`

Same shape as `ProfileResponse` (updated row).

### Flutter UX

- Debounce not required — save on explicit **Save** or per-section sheet confirm.
- On success: snackbar **Profile updated**; refresh `ProfileController` + About tab.
- Send **dirty fields only** to match partial-update semantics.

## PATCH `/users/me/avatar` — update avatar

Two-step flow (avatar binary is **not** in profile PATCH):

```text
1. POST /api/v1/files/upload   (multipart, type=AVATAR)
2. PATCH /api/v1/users/me/avatar
```

### Request

```json
{
  "avatar_file_id": "uuid-from-file-service"
}
```

### Response `200`

`ProfileResponse` with new `avatar_url` (presigned URL from file-service).

### Rules

- `avatar_file_id` required; server validates file exists via Feign.
- Invalid/missing file → `400 INVALID_FILE` or `404`.
- After success, update header avatar immediately (optimistic URL from upload response is OK until PATCH returns).

Entry points: Profile shell tap avatar (own), Edit screen avatar row (if added).

## Settings (separate from profile PATCH)

Profile **text** fields ≠ app **settings**. Do not mix into one PATCH.

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/users/me/settings` | Language, theme, notifications, privacy, `fcm_token` |
| PATCH | `/users/me/settings` | Partial update |

### PATCH settings example

```json
{
  "language": "km",
  "theme": "dark",
  "notifications": {
    "likes": true,
    "comments": true,
    "chat": true,
    "payments": true
  },
  "privacy": {
    "profile_visible": true,
    "show_activity": true
  },
  "fcm_token": "firebase-device-token"
}
```

`language`: `en` \| `km` · `theme`: `light` \| `dark` \| `system`

Wire from **Settings module** (`Prompt Frontend/Screen prompt/setting/`), not Edit Profile — unless product explicitly merges UI later.
