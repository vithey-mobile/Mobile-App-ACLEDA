## v1 — Backend-supported fields (ship with `USE_MOCK_API=false`)

These **must** call `PATCH /api/v1/users/me` (dirty fields only):

| UI section | API field | Notes |
|------------|-----------|-------|
| Display name | `full_name` | Required non-empty on save |
| Bio (optional block at top) | `bio` | Max 2000 chars |
| Education — university row | `university` | Single string in v1 |
| Education — major | `major` | Optional row or combined sheet |
| Graduation year | `graduation_year` | Integer picker 1900–2100 |
| Links — Telegram | `telegram_link` | Validate URL, max 500 |
| Links — Facebook | `facebook_link` | Validate URL, max 500 |

**Avatar** (if shown on this screen or from shell):

```text
POST /files/upload (type=AVATAR) → PATCH /users/me/avatar { avatar_file_id }
```

Prefill from `GET /users/me` on screen open.

## Save behavior

1. Validate v1 fields client-side (length, URL format, graduation year range).
2. Build `UpdateProfileRequest` with **changed fields only**.
3. `PATCH /api/v1/users/me`.
4. On `200`: snackbar **Profile updated**; `Get.back(result: updatedProfile)`.
5. On error: show field errors or snackbar; keep form dirty.

Optional: optimistic UI for name/bio — rollback on failure.

## Privacy

- Contact fields (phone/email): **not** profile-service v1 — link to Settings when implemented
- Social links on public profile: visible to visitors via `GET /users/{id}`
