# 03 - Profile Posters Prompt

Build the paginated Posters tab shown in `profile_home.png`.

## Behavior

- Fetch `GET /api/v1/users/{userId}/posts?type=POSTER`.
- Render a vertical list using the shared media `PosterPostCard`.
- Preserve server order, paginate, de-duplicate by post ID, and retain scroll position.
- Tap card/media → Post Detail.
- Like/Comment/Share use shared media prompts.

## Owner/visitor rules

- Own cards never show self-Follow.
- Visitor relationship is primarily controlled by Profile header; avoid repeated Follow on every card if redundant.
- Owner overflow Edit/Delete appears only when backend contracts exist; Delete confirms.
- Visitor sees only posts permitted by server visibility.

## States

- Skeleton cards, loaded, empty, refresh, pagination footer/error.
- Owner empty: **Create your first poster**.
- Visitor empty: **No posters yet**.
- One malformed/deleted post does not break the tab.

## Reuse

- `../media/card_poster/01.poster_sample.md`.
- `../media/02.comment.md`.
- `../media/04.share.md`.

## Testing

- Only POSTER type renders.
- Owner/visitor action differences are correct.
- Pagination, refresh, shared counts, and tab restoration work.
- Tall images remain uncropped and large text does not overflow.

## Output

Deliver a reusable Profile Posters tab backed by the shared regular Poster card.
