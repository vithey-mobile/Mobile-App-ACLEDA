## Usage model (Poster / Applier)

There is **no role picker**. Same tab for every owner; content follows usage:

| Prompt label | Meaning | Applied Jobs tab |
|--------------|---------|------------------|
| **Poster (HR)** | Posts and manages jobs | Often empty; **dev mock may seed 4 rows** to exercise UI |
| **Applier (Student)** | Applies with CV | List of applications + status pills |

- Prompts use **Poster** / **Applier** (or HR / Student) — **not** real display names.
- Never hide this tab because the user “is HR”; empty state is valid when there are no applications.

## Layout — with data

Compact list rows (applicant perspective):

| Field | Spec |
|-------|------|
| Job title | Bold |
| Company | Muted |
| Applied date | Relative (`company · N days ago`) |
| Status pill | Pending / Review / Accepted / Rejected |
| Padding | **20px** horizontal (list + empty state) |
| Tap | Application status screen |

## Data

- `GET /api/v1/users/me/job-applications?page=&limit=`
- Or `GET /api/v1/job-applications?applicant_id=me`

```json
{
  "id": "app-uuid",
  "job_post_id": "uuid",
  "job_title": "Web Developer",
  "company": "Example Co",
  "status": "PENDING",
  "applied_at": "2026-07-07T10:00:00Z"
}
```

Dev mock: **4** applied jobs with varied statuses (Pending, Review, Accepted, Rejected).
