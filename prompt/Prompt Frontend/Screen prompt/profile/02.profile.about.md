# 02 - Profile About Prompt

Build the About tab shown in `Prompt Frontend/screen image/profile/profile_about.png`.

## Sections

- **Personal Detail:** name, bio, university, major/department, graduation year, and only approved extended fields.
- **Links:** Telegram, Facebook, and approved portfolio/site links.
- **Contact Info:** only fields explicitly public for visitors; optional **Only you** section for owner when contract exists.

The reference shows Age, Working, Department, links, and phone. Current profile schema only defines full name, bio, university, major, graduation year, Telegram, and Facebook. Hide unsupported/private fields until schema and visibility settings exist.

## Privacy rules

- Public profile never obtains phone/email from auth-service behind user-profile privacy rules.
- Every extended/contact field needs a server visibility value.
- Owner may edit through Edit Profile; visitor view is read-only.
- Validate external schemes/hosts and confirm untrusted external links.
- Never render links/bio as executable HTML.

## API

- Own: `GET/PATCH /api/v1/users/me`.
- Visitor: `GET /api/v1/users/{userId}` public projection.

Add schema/privacy contracts before Age, company/role, department, location, portfolio, phone, or email appear.

## States

- Section skeleton on first profile load.
- Hide empty fields/sections cleanly.
- Owner empty state links to Edit Profile.
- Visitor empty state says no public information.
- Link launch errors remain inline and do not crash Profile.

## Accessibility/testing

- Semantic section headings and labeled values/links.
- Long values wrap; large text does not overlap.
- Verify visitor cannot see owner-only contact fields.
- Verify malformed links are blocked and missing data is omitted.

## Dependencies

- `01.profile_home.md`.

## Output

Deliver a privacy-aware About tab matching the reference while rendering only documented, permitted personal information.
