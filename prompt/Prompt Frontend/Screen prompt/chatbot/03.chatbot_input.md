# 03 - Chatbot Input and Attachment Prompt

Build the sticky ChatGPT-style Vithey AI composer.

## Visual references

- `chatbot-home.png` and `Reasoning-bot-response.png` in `Prompt Frontend/screen image/chatbot/`.

## Layout

- Rounded composer pinned above bottom safe area/software keyboard.
- Left circular plus action.
- Multiline **Ask me anything…** input.
- Right teal circular Send/paper-plane.
- Auto-grow upward from one line to a maximum, then internal scroll.
- Selected attachment chips/previews grow above input; bottom edge remains anchored.
- During response generation, Send becomes accessible **Stop generating**.

## Send lifecycle

1. Trim/validate text and supported attachments.
2. Freeze request with client idempotency/message ID.
3. Insert optimistic user message.
4. Clear composer while keeping recovery copy.
5. Add assistant Thinking placeholder.
6. Send topic/current `session_id` through repository.
7. Adopt returned session ID for a new chat.
8. Coordinate response with `04.chatbot_response.md`.

Empty trimmed text cannot send unless an approved attachment alone is supported. Keyboard Send and button Send match; newline behavior follows platform convention. Duplicate taps never duplicate turns/sessions.

## Failure/retry/edit

- Failed turn retains recoverable content with Retry/Edit.
- Retry reuses client ID and does not insert another user bubble.
- Offline never queues silently; send only after explicit Retry.
- 429 keeps draft/turn and shows cooldown.
- Stop aborts stream when supported and retains labeled partial response.

## Per-session drafts

- Preserve text/attachments per session during app session.
- Restore on session switch.
- Clear on successful send, explicit discard, logout/account switch.
- Never persist passwords/tokens/sensitive document content.

## Plus/attachment menu

Potential actions only when supported:

- Image.
- Document/PDF.
- Camera.
- Approved in-app CV/tool.

Rules:

- Privacy-preserving pickers/minimum permissions.
- Validate MIME, size, count, malware server-side.
- Private upload and short-lived authorized reference.
- Explain what content is sent to the model/provider.
- Allow remove before send.
- Never send passwords, full payment credentials, student-ID documents, or unrelated private records.

Current AI API is text-only and file-service has no AI attachment contract. Hide/disable unsupported plus actions; never pretend the model read an uploaded file.

## Required backend contract

- Client message/idempotency ID.
- Streaming/cancellation protocol.
- Private AI attachment references and supported modalities.
- Edit/resend branch/truncation semantics if enabled.

## Accessibility/responsive behavior

- Label plus, input, attachment/removal, Send/Stop, retry/edit, limits, errors.
- Minimum `44 × 44` actions.
- Keyboard/focus traversal, large text, screen readers, reduced motion.
- Composer remains visible at `320 px`, landscape, and keyboard open.

## Architecture


## Testing and acceptance criteria

- Matches reference rounded input and stays pinned.
- Multiline/attachments grow upward without covering messages.
- Send/Stop, duplicate protection, draft restoration, retry/edit, offline/429 work.
- Unsupported attachments are not presented as functional.
- Keyboard and large text never overflow.

## Output

Deliver a reliable sticky AI composer with safe send lifecycle, drafts, cancellation, and feature-gated attachments.
