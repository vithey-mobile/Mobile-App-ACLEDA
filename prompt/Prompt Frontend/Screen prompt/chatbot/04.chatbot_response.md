# 04 - Chatbot Thinking, Streaming, and Rich Response Prompt

Build the Vithey AI assistant response UI, matching `Prompt Frontend/screen image/chatbot/Reasoning-bot-response.png` and supporting ChatGPT-style rich content.

## Thinking UI

- Vithey assistant mark at left.
- Animated teal dots while waiting/starting.
- Truthful optional status: Thinking, searching approved sources, reading attachment, generating response.
- Reduced-motion uses static indicator/live-region update.

Never expose hidden chain-of-thought, system prompts, provider traces, or raw tool arguments. A “Reasoning” affordance may show a concise user-facing summary/steps/sources only.

## Streaming

- Prefer documented SSE/event stream.
- Append deltas into one assistant message, batching UI updates.
- Render incomplete Markdown safely; finalize parsing on completion.
- Auto-scroll only near bottom; otherwise show Jump to latest.
- Stop keeps partial response labeled stopped.
- Retry/reconnect never duplicates received content.
- Current backend returns complete `reply`; support non-streaming fallback using the same state.

## Rich blocks

Safely support:

- Paragraphs/line breaks.
- Markdown headings, bold, italic, inline code.
- Ordered/unordered/task lists.
- Blockquotes/callouts.
- Syntax-highlighted fenced code with language, horizontal scroll, Copy code.
- Horizontally scrollable tables.
- Safe links with visible domain/confirmation.
- Structured citations/source cards.
- Structured approved images/file cards.
- Tool-result/warning/error cards.
- Suggested follow-up chips.

Never render arbitrary raw HTML, JavaScript, untrusted WebViews, or executable content. Sanitize links and cap pathological size/nesting.

## Message actions

Assistant completed:

- Copy.
- Regenerate when supported.
- Thumbs up/down when supported.
- Optional Read aloud.

User messages are owned by Input prompt; Edit/Retry need defined branch/idempotency behavior. Hide all nonfunctional actions.

## States

- Waiting/thinking.
- Streaming.
- Complete.
- Stopped/cancelled partial.
- Provider/network interrupted partial with Retry/Continue only when supported.
- Rate limited.
- Safety refusal.
- Malformed rich block safe fallback.

## Streaming contract extensions

Define event schema for:

- Session/message start.
- Text/content-block delta.
- Tool/status summary.
- Citation/attachment block.
- Completion.
- Usage/rate limit.
- Error/cancellation.

Add message IDs and idempotency, regenerate/edit semantics, feedback endpoint, and structured blocks. Feature-gate until documented.

## Security/privacy

- Treat citations/tool data as untrusted.
- Do not claim private app data access without approved consented tool flow.
- Do not render secrets/tokens/raw provider errors.
- Finance/medical/legal/high-stakes guidance identifies limitations and encourages authoritative verification.

## Performance/accessibility

- Avoid whole-list rebuild per token.
- Code/tables scroll horizontally without widening screen.
- Select/copy text remains usable.
- Announce streaming at a non-spammy cadence and final/error states.
- Label actions and assistant role.
- Support screen readers, reduced motion, high contrast, large text.

## Testing and acceptance criteria

- Thinking matches reference without exposing chain-of-thought.
- Streaming/non-streaming create one stable assistant message.
- Markdown, lists, code/copy, tables, links, citations, structured files/images render safely.
- Stop/interruption/retry/rate-limit/malformed blocks work.
- Long code/tables/large text never overflow.
- Unsupported actions are feature-gated.

## Output

Deliver a safe, performant ChatGPT-style assistant response renderer with truthful thinking, streaming fallback, rich structured blocks, and accessible actions.
