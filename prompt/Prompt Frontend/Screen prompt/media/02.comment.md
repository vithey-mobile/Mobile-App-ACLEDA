# 02 - Facebook-Style Post Comments Prompt

Build the reusable comment experience used by regular Poster, Video, and Job cards in the Home feed.

## Visual reference

- `Prompt Frontend/screen image/home/comment.png`.

## Goal

Tapping a post's Comment icon opens a draggable, keyboard-safe bottom sheet where users can read, paginate, create, like, and reply to comments without leaving Home or losing feed scroll position.

## Entry contract

```dart
openComments(String postId)
```

- Use the stable post ID, never a list index.
- Comment tap stops card-body navigation.
- Same component works for POSTER, VIDEO, and JOB.

## Sheet layout

Use an is-scroll-controlled modal bottom sheet with rounded top corners and a `DraggableScrollableSheet` or equivalent.

1. Centered dark drag handle with semantic dismiss action.
2. Engagement summary: Like, Comment, Share counts synchronized with the post.
3. Scrollable comments list.
4. Composer pinned above bottom safe area and keyboard.

The list—not Home—scrolls while open. Swipe down, outside tap, system Back, or semantic close dismisses and returns to the same Home position.

## Comment row

- Author avatar left.
- Rounded light bordered/filled bubble right.
- Bold author name and multiline comment text.
- Metadata/actions below: **Like**, **Reply**, relative time.
- Long names/text wrap safely.
- Newest-first for this sheet; newly submitted comments appear immediately at the top and scroll into view.
- Use server timestamps and stable `commentId`.

## Composer

- Rounded light-gray text field with **Write a comment…**.
- Teal circular paper-plane Send action.
- Auto-grows upward to a maximum, then scrolls internally.
- Remains visible using `MediaQuery.viewInsets.bottom` when keyboard opens.
- Send enabled only for non-empty trimmed content and no duplicate submission.
- Keyboard Send and button Send behave identically.
- Preserve an unsent per-post draft during the current session.

## Create comment

1. Validate/trim against backend maximum length.
2. Generate temporary client ID.
3. Insert optimistic comment at top using current-user summary.
4. Increment visible comment count once across Home/Post Detail caches.
5. Clear composer and send `POST /api/v1/posts/{postId}/comments`.
6. On success, replace temporary ID/content metadata without reordering or incrementing again.
7. On failure, retain a failed row with **Retry** and **Remove**; reconcile count exactly.

Rapid Send taps never duplicate a comment. Render text safely as text/approved mentions, never executable HTML.

## Like and Reply

- Comment Like toggles current-user reaction and count when a documented endpoint exists.
- Reply enters **Replying to {name}** composer mode with Cancel.
- Submit replies with structured `parent_comment_id`, not only `@name` text.
- Render one compact reply level in the sheet; deeper threads open a thread/detail view.
- Current backend does not define comment reactions or reply parents. Hide/disable these actions behind feature flags until contracts exist; never pretend they persisted.

## Loading and pagination

- Initial: 3–5 comment bubble skeletons.
- Empty: **No comments yet. Be the first to comment.** with active composer.
- Initial error: inline Retry without dismissing sheet.
- Load older comments near list end.
- Pagination failure retains loaded items and shows footer Retry.
- Cache per post for instant reopen, then refresh.
- De-duplicate by comment ID and preserve optimistic rows during refresh.

## API

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/v1/posts/{postId}/comments` | Paginated comments |
| `POST` | `/api/v1/posts/{postId}/comments` | Create comment |

Required response fields:

- Comment ID.
- Author ID/name/avatar.
- Text.
- Created timestamp.
- Current-user ownership.
- Optional reaction/reply summary when supported.
- Deterministic pagination/order.

Required extensions for full reference actions:

- Comment reaction endpoint/state.
- `parent_comment_id` and replies pagination.
- Idempotency/client-message ID for safe retries.

## Security and moderation

- Server verifies post visibility and comment permission.
- Sanitize display and validate length/rate limits.
- Do not expose blocked/deleted-user private data.
- Provide report/delete-own options only when contracts exist.
- A deleted/unavailable post closes or disables composer with explanation.

## Accessibility

- Label sheet, dismiss, engagement counts, author/comment, Like, Reply, reply target, composer, Send, retry/remove, and states.
- Announce optimistic send, success, and failure non-disruptively.
- Minimum `44 × 44` targets.
- Logical focus order and focus restoration to originating Comment action.
- Support large text, reduced motion, keyboard traversal, and screen readers.

## Architecture

```text
lib/modules/home/widgets/comments/
  comment_bottom_sheet.dart
  comment_list.dart
  comment_bubble.dart
  comment_composer.dart
  comment_reply_banner.dart

lib/data/models/comment_model.dart
lib/data/repositories/comment_repository.dart
```

- One normalized comment cache shared by Home and Post Detail.
- Sheet owns presentation; controller/repository owns fetching/mutations.

## Testing and acceptance criteria

- Matches `comment.png`: handle, metrics, avatar/bubble list, Like/Reply metadata, pinned composer, teal Send.
- Opens for the exact post type/ID and preserves Home scroll.
- Keyboard never covers composer.
- Valid send appears at top, increments once, and reconciles without duplicates.
- Failure supports Retry/Remove and restores correct count.
- Empty/loading/error/pagination/reply/large-text states do not overflow.
- Like/Reply remain feature-gated until backend support exists.
