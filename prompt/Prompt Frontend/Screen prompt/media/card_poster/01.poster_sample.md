# 01 - Regular Poster Card Prompt

Build the Facebook-style regular `POSTER` card used in Home and Profile.

## Visual reference

- `Prompt Frontend/screen image/home/poster .png`.
- The HTML/Heng Liza example is fixture data only.

## Typed input

```dart
PosterFeedPost(
  id,
  author,
  content,
  mediaUrl,
  createdAt,
  reactionCount,
  commentCount,
  shareCount,
  userReacted,
  isFollowingAuthor,
)
```

Render this card only for `type == POSTER`.

## Layout

1. Shared author header:
   - Circular avatar.
   - Bold author name.
   - Relative time.
   - Right-side Follow/Following action for other users.
2. Caption/body text with safe mentions and multiline wrapping.
3. Full-width poster image with preserved aspect ratio and `BoxFit.contain`.
4. Engagement row: Like, Comment, Share counts.

Use white surface, subtle border/shadow, compact spacing, and stable card key by post ID.

## Media rules

- Never crop readable poster details, logos, QR codes, or text.
- Load a display-sized cached image with placeholder and error fallback.
- Tap media/body opens Post Detail.
- Poster image is content, not structured business data; never parse QR/OCR to trigger actions.
- Provide useful alt semantics from caption/author, not unreliable OCR.

## Follow behavior

- Visitor, not following → teal **Follow**.
- Visitor, following → accessible **Following**.
- Own post → no Follow button.
- Loading keeps button dimensions stable.
- Follow/unfollow is optimistic with rollback.
- Update every visible card/profile for the same author.
- Follow action never opens Post Detail.

APIs:

- `POST /api/v1/users/{authorId}/follow`.
- `DELETE /api/v1/users/{authorId}/follow`.

## Engagement actions

- Like toggles optimistically through `/posts/{postId}/reactions`.
- Comment opens `../02.comment.md` for this post.
- Share opens `../04.share.md` for this post.
- Action taps stop card-body navigation.
- Counts reconcile from server and never go negative.

## Owner behavior

- Hide self-Follow.
- Optional overflow Edit/Delete only when owner contracts exist.
- Delete requires confirmation and removes only this post after server success.
- Profile use may omit repeated Follow action because header already owns relationship state.

## States

- Skeleton card.
- Loaded.
- Image loading/error.
- Reaction mutation/error.
- Follow mutation/error.
- Deleted/unavailable.
- Long-content collapsed/expanded when needed.

## Accessibility and responsive behavior

- Label author, time, poster media, Follow state, Like/Comment/Share counts and states.
- Minimum `44 × 44` targets.
- Support `320 px`, large text, long author/caption, and tablet max width.
- Do not use color alone for relationship/reaction state.

## Architecture

```text
lib/modules/home/widgets/
  post_card.dart
  post_author_header.dart
  poster_post_card.dart
  post_media.dart
  feed_action_bar.dart
```

`PosterPostCard` supplies poster body and Follow action to the shared `PostCard`; API calls remain in controller/repository.

## Testing and acceptance criteria

- Matches `poster .png` hierarchy and displays uncropped media.
- Dispatches only POSTER data.
- Own card never shows Follow.
- Follow updates all cards by author and rolls back on error.
- Like/Comment/Share receive exact post ID and do not trigger body navigation.
- Image/long-text/loading/error/large-text states do not overflow.

Deliver one reusable regular Poster card for Home/Profile with faithful media, Follow, and shared engagement behavior.
