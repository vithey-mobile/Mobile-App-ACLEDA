# 02 - Video Post Card Prompt

Build the social `VIDEO` card used in Home and Profile.

## Visual references

- Home shell: `Prompt Frontend/screen image/home/home screen.png`.
- Profile video style: `Prompt Frontend/screen image/profile/profile_video.png`.
- No dedicated Home video mockup exists; use the shared card shell and the playback rules below.

## Typed input

```dart
VideoFeedPost(
  id,
  author,
  content,
  mediaUrl,
  thumbnailUrl,
  duration,
  processingState,
  createdAt,
  reactionCount,
  commentCount,
  shareCount,
  userReacted,
  isFollowingAuthor,
)
```

Render only for `type == VIDEO`.

## Layout

1. Shared author header: avatar, name, relative time, visitor Follow/Following.
2. Caption text.
3. Responsive video area with thumbnail/player.
4. Overlaid centered play/pause control, duration, mute state as appropriate.
5. Engagement footer: Like, Comment, Share.

Profile may render a compact thumbnail card; Home renders the full social card. Both use the same model and navigation.

## Playback behavior

- Start paused with thumbnail unless product explicitly enables feed autoplay.
- If autoplay is enabled: only the most visible eligible video plays, starts muted, respects data saver/reduced motion, and pauses off-screen/app background.
- Never play multiple cards simultaneously.
- Tap play starts current video and pauses the previous one.
- Tap media may toggle controls; explicit expand opens Post Detail/full player.
- Show progress/scrubber, play/pause, mute, duration, buffering, replay, and full-screen controls appropriate to platform.
- Preserve aspect ratio; use letterboxing rather than destructive crop when needed.
- Dispose/release controllers when items leave the managed active range.

## Processing and failure states

- `PROCESSING`: thumbnail/progress card with **Video is processing**; no fake playback.
- `READY`: playable media.
- `FAILED`: unavailable message and owner Retry/replace path only when supported.
- Network buffering: inline progress without freezing feed.
- Playback error: Retry/Open detail.
- Deleted/private/blocked: safe unavailable state.

## Follow and owner rules

- Other user: Follow/Following with optimistic author-level sync.
- Own video: no self-Follow.
- Profile header may own Follow, allowing card header action to be omitted there.

## Engagement actions

- Like toggles `/posts/{postId}/reactions` optimistically.
- Comment opens `../02.comment.md`.
- Share opens `../04.share.md`.
- All actions use exact post ID and stop card navigation/play toggling.

## Backend/media contract

Feed VIDEO response should include:

- Video URL or authorized stream reference.
- Thumbnail URL.
- MIME/container.
- Duration and dimensions/aspect ratio.
- Processing state.
- Optional HLS/adaptive variants when supported.
- Shared social counts/current-user state.

Current basic post response lacks most video metadata. Define it before advanced playback. Do not download the full video to generate list thumbnails on device.

## Performance

- Lazy initialize players near viewport.
- Use a small controller pool, not one permanently active player per feed item.
- Cache thumbnails; stream video with range/adaptive support.
- Avoid rebuilding the full feed on progress ticks.
- Pause on navigation, app background, incoming media focus, and another video start.
- Honor platform audio focus.

## Accessibility

- Announce author, caption, duration, processing/play state, controls, and engagement.
- Provide play/pause/mute labels that update with state.
- Support captions/subtitles when supplied.
- Minimum `44 × 44` controls and adequate contrast.
- Reduced motion disables autoplay.

## Architecture

```text
lib/modules/home/widgets/
  video_post_card.dart
  managed_video_player.dart
  video_thumbnail.dart
  video_controls.dart

lib/modules/home/services/feed_video_coordinator.dart
```

One feed video coordinator owns active playback and lifecycle. Card widgets do not independently autoplay.

## Testing and acceptance criteria

- Dispatches only VIDEO data and follows shared card styling.
- Only one video plays; off-screen/background pause works.
- Processing, buffering, failed, replay, and network retry states work.
- Like/Comment/Share use correct post ID without toggling player/card route.
- Own card hides Follow.
- Large text, landscape/full-screen return, long caption, and rapid list recycling do not leak controllers or overflow.
