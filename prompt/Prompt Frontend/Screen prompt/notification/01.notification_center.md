# 01 — Notification Center (Facebook-Style Inbox)

Build the **Facebook-style notification inbox** from `Prompt Frontend/screen image/notification/notification.png`.

## Route

| Field | Value |
|-------|-------|
| Route | `AppRoutes.notification` |
| Module | `lib/modules/notification/` |
| Backend | `notification-service` :8088 |
| Auth | Required |
| Entry | Home bell icon, push tap, deep link |

## Search entry (global)

The notification reference image shows a **search icon** in the app bar. This is **not** inbox filtering — it opens the same global search screen as Home and Chat.

```dart
IconButton(
  icon: const Icon(Icons.search),
  tooltip: 'Search',
  onPressed: () => Get.toNamed(AppRoutes.search),
),
```

Place **before** the settings icon. No `GET /notifications?search=` in v1 — backend search is people + posts only (`Prompt Backend/_shared/SEARCH.md`).

## App bar (`notification_app_bar.dart` or inline)

| Element | Spec |
|---------|------|
| Title | **Notifications**, bold, left-aligned |
| Search | `Icons.search` — opens global `AppRoutes.search` (same as Home) |
| Settings | `Icons.settings` → notification preferences in Settings |
| SafeArea | Yes; min tap target `44×44` |

## Filter bar (`notification_filter_bar.dart`)

| Chip | Behavior |
|------|----------|
| **All** | Default; `GET /notifications?page&limit` |
| **Unread** | Server-backed `?is_read=false` — never client-filter only loaded page |

Selected chip: pale teal background (`AppColors.primary` at ~12% opacity), semibold label.

Preserve scroll position per filter when switching back.

## Group headers (`notification_group_header.dart`)

Facebook-style sections derived from `createdAt` + read state:

| Section | Rule |
|---------|------|
| **New** | Unread items from last 24h (or all unread at top — match reference) |
| **Today** | Read items from today |
| **Yesterday** | Read items from yesterday |
| **Earlier** | Everything older |

Optional **See all** on New section only when collapsing is implemented.

## Notification row (`notification_item.dart`)

Facebook/Meta pattern:

| Zone | Spec |
|------|------|
| Left | `UserAvatar` 48dp — actor photo, or type icon if no actor |
| Badge | Small circular overlay bottom-right — heart, comment, share, person, briefcase, chat, payment, AI sparkle, megaphone |
| Center | Human-readable line — actor name **bold**, action text regular |
| Subtitle | Relative time — `2 minutes ago`, `Yesterday` |
| Right | Teal unread dot when `!isRead`; ellipsis `…` |
| Background | Unread: subtle tint (`primary` 4%); Read: transparent |

### Row interactions

| Gesture | Action |
|---------|--------|
| Tap row | Mark read (if unread) → navigate by type |
| Tap `…` | Open bottom action sheet — **does not** mark read or navigate |

## Bottom action sheet (`notification_action_sheet.dart`)

Slides up from bottom (Facebook-style):

```
┌─────────────────────────────────────┐
│            ─── handle ───           │
│  Kimheang liked your post           │  optional preview
│  ✓  Mark as read                    │
│  🗑 Delete notification  (red)      │
└─────────────────────────────────────┘
```

| Action | Rules |
|--------|-------|
| Mark as read | Only when unread; `PATCH /notifications/{id}/read` |
| Delete | Red destructive; confirm dialog first |

Pass immutable `notificationId` — never list index.

## Delete confirmation (`delete_notification_dialog.dart`)

- Title: **Delete notification?**
- Body: **This removes only this notification from your list. The related post, application, message, or payment will not be deleted.**
- Actions: Cancel | Delete (red)

## Global unread badge (Home)

- Shared `NotificationRepository.unreadCount` observable
- Fetch `GET /notifications/unread-count` on app start, resume, after mutations
- Display on Home bell — cap `99+`
- Decrement exactly once per mark-read/delete
- Clear on logout

## Pagination & refresh

| Action | Spec |
|--------|------|
| Pull to refresh | Reload current filter page 1 |
| Infinite scroll | Load next page at ~80% scroll; footer spinner |
| Error | Footer Retry keeps loaded rows |
| Dedupe | Key by `notificationId`; ignore duplicate FCM + REST |

## Loading & empty states

| State | UI |
|-------|-----|
| Initial load | 6–8 shimmer skeleton rows |
| All empty | **No notifications yet** |
| Unread empty | **You're all caught up** |
| Error | `AppErrorWidget` with Retry |

## Architecture rules

- One normalized store keyed by `notificationId`
- All / Unread / grouped views derive from same store
- Routing maps live in controller or `NotificationRouter` — not in row widgets
- Never parse `title`/`body` strings to infer destination

## Dark mode

- Row surface: `context.scheme.surface`
- Unread title: `FontWeight.w700`
- Muted time: `context.appColors.muted`
- Unread dot: `AppColors.primary` — also use accessibility label, not color alone
