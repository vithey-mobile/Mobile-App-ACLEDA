# 05 — Notification REST API & Backend Contract

Backend-ready contract for **notification-service**, event pipeline, and Firebase Admin SDK push.

> **Spring Boot implementation:** `Prompt Backend/services/notification-service/UPGRADE_FOR_UI.md`

## Service topology

```text
notification-service :8088
├── PostgreSQL — notifications, device_tokens
├── Redis — unread_count cache per user (optional)
├── RabbitMQ consumer — domain events
└── Firebase Admin SDK — FCM send

API Gateway :8080
└── /api/v1/notifications/**
```

## REST API (canonical)

Base: `API_BASE_URL` — Flutter constants **omit** `/api/v1` prefix.

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/notifications?page=&limit=&is_read=` | Paginated inbox |
| GET | `/notifications/unread-count` | Badge count |
| PATCH | `/notifications/{id}/read` | Mark one read |
| PATCH | `/notifications/read-all` | Mark all read |
| DELETE | `/notifications/{id}` | Delete one |
| POST | `/notifications/devices` | Register FCM token |
| DELETE | `/notifications/devices/{token}` | Remove FCM token |

### Unread filter

```
GET /notifications?page=1&limit=20&is_read=false
```

Server must filter — client-only filtering of loaded pages is **not** acceptable.

### Device register

```json
POST /notifications/devices
{ "fcm_token": "...", "platform": "ANDROID" }
```

Platform: `ANDROID` | `IOS`.

| `ai.response.ready` | ai-service | Requesting user | `AI` |
| `system.announcement` | notification-service | Target users | `SYSTEM` |

## notification-service flow

```text
1. Consume event from RabbitMQ
2. Validate recipient != actor (no self-notify for likes etc.)
3. Build title, body, destination from event payload
4. INSERT notification row (idempotent on dedupe_key)
5. Load recipient device_tokens
6. Firebase Admin SDK send multicast
7. On FCM failure: log error, keep in-app row (HTTP 201 still succeeds)
```

## Firebase Admin SDK (backend)

```java
Message message = Message.builder()
    .setToken(deviceToken)
    .putData("notification_id", notification.getId().toString())
    .putData("type", notification.getType().name())
    .putData("event", notification.getEventName())
    .putData("reference_id", notification.getReferenceId())
    .putData("actor_id", actor.getId())
    .putData("actor_name", actor.getDisplayName())
    .setNotification(Notification.builder()
        .setTitle(notification.getTitle())
        .setBody(notification.getBody())
        .build())
    .setAndroidConfig(AndroidConfig.builder()
        .setPriority(AndroidConfig.Priority.HIGH)
        .setNotification(AndroidNotification.builder()
            .setChannelId(channelForType(notification.getType()))
            .build())
        .build())
    .build();

FirebaseMessaging.getInstance().send(message);
```

## Redis (optional optimization)

```
Key: notification:unread:{userId}
TTL: none
INCR on insert (unread)
DECR on mark read
Invalidate on read-all
```

Flutter still reconciles via `GET /unread-count` on resume.

## Chat vs notification-service boundary

| Concern | Owner |
|---------|-------|
| Message delivery in-app | chat-service WebSocket STOMP |
| Message push when backgrounded | notification-service FCM |
| Inbox row for chat | notification-service |
| Thread history | chat-service REST |

chat-service publishes `chat.message.sent`; it does **not** call Firebase directly.

## Required backend extensions

1. **`DELETE /notifications/{id}`** — owner-only single delete
2. **`is_read` query param** on list — server unread filter
3. **`POST_SHARE` type** + `post.shared` event from content-service
4. **`AI` type** + `ai.response.ready` from ai-service
5. **Structured `destination` object** in list DTO (not just `reference_id`)
6. **`dedupe_key`** on insert for idempotency
7. **`event` field** for subtype disambiguation (`JOB` + status vs received)

## Error mapping

| HTTP | Code | Flutter action |
|------|------|----------------|
| 404 | `NOT_FOUND` | Remove stale row from Isar |
| 401 | `UNAUTHORIZED` | Refresh token / re-login |
| 403 | `FORBIDDEN` | Snackbar — not your notification |
| 409 | `DUPLICATE` | Treat as success (idempotent read) |
| 5xx | — | Retry with backoff; keep cache |
