# 06 — Notification Page (Card-Style Redesign)

Restyle the **Notification inbox** for Vithey App in Flutter, matching:

- `Prompt Frontend/screen image/notification/notification_page.png`

> This is a **visual redesign** of the existing inbox built by
> `01.notification_center.md`. Keep all behavior from that prompt (data store,
> pagination, mark-read, delete, unread badge, deep-link routing) and change
> only the layout/styling described here. Where the two prompts conflict on
> visuals, this file wins.

## Quick info

| Field | Value |
|---|---|
| Route | `AppRoutes.notifications` (existing) |
| Flutter module | `lib/modules/notification/` (existing) |
| Backend service | `notification-service` |
| Auth required | Yes |
| Entry point | Home bell icon, push tap, deep link |

## Goal

Show the user's notifications as rounded cards grouped by day, filterable by
All / Read / Unread, with the same interactions as the current inbox.

## Visual requirements

Match `notification_page.png`. All colors must come from `Theme.of(context)`
/ `colorScheme` / semantic app colors so the screen looks correct in **both
light and dark mode** — never hardcode white, black, or teal hex values.

- Theme background (`scaffoldBackgroundColor`).
- App bar:
  - Back arrow on left.
  - Bold title: **Notification**.
  - Thin divider below.
- **Segmented filter pill** (replaces the old two-chip filter bar):
  - Centered below the app bar.
  - One rounded full-pill container in a muted surface color
    (`surfaceVariant` / grey tone that adapts to theme).
  - Three segments: **All**, **Read**, **Unread**.
  - Selected segment: primary-colored pill with white/on-primary bold label.
  - Unselected segments: muted text, transparent background.
  - Animate the selection change (slide or fade, ~150ms).
- **Group headers**: plain muted/heading text above each group, derived from
  `createdAt`:
  - **Today**
  - **Yesterday**
  - **Last week** (2–7 days old)
  - **Earlier** (older than 7 days; only when such items exist)
- **Notification card** (replaces the old flat row):
  - Rounded card (~12 radius) with soft `subtleShadow`.
  - **Fixed height (~78px)** — every card is exactly the same size; the
    action line is a single line with ellipsis so content never wraps.
  - **Card background**: always plain `cardSurface` (white in light mode,
    dark surface in dark mode) for both read and unread — no tinted
    background. Unread state is indicated by the accent tab alone.
  - **Left accent tab** — **unread only**:
    - Shown only while the notification is unread; read cards have **no**
      accent tab.
    - **Flush against the card's left edge** — no left border radius;
      rounded on the **right side only** (like a tab sticking out of the
      edge).
    - Thin: ~4px wide, primary-colored.
    - **Not full height**: ~60% of the card height, vertically centered.
    - When a card is marked as read, the tab fades out (a short animation
      is a plus).
  - `UserAvatar` (~44dp) — actor photo, initials fallback, or type icon when
    there is no actor.
  - Text column:
    - Actor name — bold, heading color (e.g. **Julie**).
    - Action line — regular weight (e.g. `Like your post`), heading color;
      unread items may use heavier weight per existing behavior.
    - Relative time — muted, smaller (`30min ago`, `2h ago`,
      `Yesterday at 3:21 PM`, `8 days ago`).
  - Trailing ellipsis `…` button — opens the existing bottom action sheet;
    must not mark read or navigate.
  - ~10–12px vertical gap between cards; 16px page padding.
- Ink splash on card tap must render above the card surface (wrap in
  `Material`/`InkWell` correctly).

## Filter behavior

| Segment | Behavior |
|---|---|
| **All** | Default; `GET /notifications?page&limit` |
| **Read** | Server-backed `?is_read=true`; fall back to client filter only if backend lacks the param — do not fake pagination |
| **Unread** | Server-backed `?is_read=false` (existing) |

- Preserve scroll position per filter when switching back.
- Keep pull-to-refresh and infinite scroll from the existing implementation.

## Grouping rules

Compute from `createdAt` in local time:

| Group | Rule |
|---|---|
| Today | Same calendar day |
| Yesterday | Previous calendar day |
| Last week | 2–7 days ago |
| Earlier | Older than 7 days |

Time label format inside cards:

- Under 1h: `{m}min ago`
- Under 24h: `{h}h ago`
- Yesterday: `Yesterday at {h:mm AM/PM}`
- Older: `{d} days ago` (or short date past ~2 weeks)

Reuse/extend the existing `notification_grouping.dart` and
`notification_display_text.dart` utilities rather than duplicating logic.

## Interactions (unchanged from `01.notification_center.md`)

- Tap card → mark read (if unread) → navigate by type.
- Tap `…` → bottom action sheet (Mark as read / Delete with confirmation).
- Unread badge on Home bell stays in sync.
- Pagination, dedupe by `notificationId`, pull-to-refresh, error footer Retry.

## Loading & empty states

| State | UI |
|---|---|
| Initial load | Shimmer skeleton cards matching the new card shape |
| All empty | **No notifications yet** |
| Read empty | **Nothing here yet** |
| Unread empty | **You're all caught up** |
| Error | `AppErrorWidget` with Retry |

## Testing

- Layout matches `notification_page.png`: segmented pill, day groups, accent-bar cards.
- Segmented control switches All/Read/Unread with correct server queries.
- Groups bucket correctly across Today/Yesterday/Last week/Earlier boundaries.
- Time labels render in the reference formats.
- Card tap marks read and navigates; ellipsis opens the action sheet only.
- Unread cards show the centered ~60%-height accent tab (flush left,
  right-rounded); read cards show no tab. Card background stays plain
  `cardSurface` in both states, per the reference card image.
- Marking a card as read fades the accent tab out (a short animation is a
  plus).
- Cards, accent bar, pill, and text remain legible in dark mode.
- No overflow on 320px width or with large system text.

## Output

Restyled notification inbox matching `notification_page.png`, keeping all
existing behavior (filters, pagination, actions, badge sync, routing) and
fully theme-aware for light and dark mode.
