# 02 — Notification Types, Copy & Deep-Link Routing

Typed enum, Facebook-style display copy, badge icons, and navigation for all notification categories.

```dart
NotificationType normalizeType(String backendType, {String? eventName}) {
  return switch ((backendType, eventName)) {
    ('JOB', 'job.application.submitted') => NotificationType.jobApplicationReceived,
    ('JOB', 'job.application.status_changed') => NotificationType.jobApplicationStatus,
    ('PAYMENT', 'payment.overdue') => NotificationType.paymentOverdue,
    ('PAYMENT', _) => NotificationType.paymentDue,
    ('AI', _) => NotificationType.aiAssistantResponse,
    // ... map remaining
    _ => NotificationType.system,
  };
}
```

## Type catalog (9 primary + extensions)

### 1. New message (`chatMessage`)

| Field | Value |
|-------|-------|
| Trigger | `chat.message.sent` — recipient not in active thread |
| Recipient | Conversation participant |
| Copy | **{actor}** sent you a message. |
| Badge icon | `Icons.chat_bubble` |
| Badge color | `AppColors.primary` |
| Destination | `ChatDetailArgs(conversationId)` |
| Realtime | WebSocket STOMP updates thread; FCM only when backgrounded |

**Do not** put full message text in push body when E2E sensitive — use: *You have a new message*.

### 2. Like post (`postLike`)

| Field | Value |
|-------|-------|
| Trigger | `reaction.added` on user's post |
| Copy | **{actor}** liked your post. |
| Badge | `Icons.favorite` — red/pink |
| Destination | `PostDetail(postId)` |
| Skip | Self-like — never notify |

### 3. Comment (`postComment`)

| Field | Value |
|-------|-------|
| Trigger | `comment.added` on user's post |
| Copy | **{actor}** commented on your post. |
| Badge | `Icons.mode_comment` — blue |
| Destination | `PostDetail(postId)` — scroll to comment when `commentId` present |

### 4. Share post (`postShare`)

| Field | Value |
|-------|-------|
| Trigger | `post.shared` — **public reshare only** |
| Copy | **{actor}** shared your post. |
| Badge | `Icons.share` — teal |
| Destination | `PostDetail(postId)` |
| Never notify | Private "Save post" / bookmark actions |

### 5. New follower (`newFollower`)

| Field | Value |
|-------|-------|
| Trigger | `follow.created` |
| Copy | **{actor}** started following you. |
| Badge | `Icons.person_add` — green |
| Destination | `ProfileArgs(userId: actorId)` |

### 6. Job application (`jobApplicationReceived` / `jobApplicationStatus`)

**Received (job owner):**

| Field | Value |
|-------|-------|
| Trigger | `job.application.submitted` |
| Copy | **{applicant}** applied for **{job title}**. |
| Badge | `Icons.work_outline` |
| Destination | `JobApplicantsArgs(jobPostId, applicationId?)` |

**Status (applicant):**

| Field | Value |
|-------|-------|
| Trigger | `job.application.status_changed` |
| Copy | Your application for **{job title}** was **{status}**. |
| Badge | `Icons.assignment` |
| Destination | My application detail *(route when implemented)* |

**Security:** Never include CV file URL or student ID in notification or push payload.

### 7. Payment notification (`paymentDue` / `paymentOverdue`)

| Field | Value |
|-------|-------|
| Trigger | `payment.due` / `payment.overdue` |
| Copy due | Payment of **{amount}** is due on **{date}**. |
| Copy overdue | Your payment of **{amount}** is overdue. |
| Badge | `Icons.payments` — amber/red |
| Destination | `AppRoutes.finance` or payment detail with `paymentId` |
| Gate | Verified AUB students only |

### 8. AI assistant response (`aiAssistantResponse`)

| Field | Value |
|-------|-------|
| Trigger | `ai.response.ready` when user started async/long AI job |
| Copy | Vithey AI finished your request. |
| Badge | `Icons.auto_awesome` — purple |
| Destination | `AppRoutes.chatbot` with `threadId` / `sessionId` |
| Note | Distinct from private `chatMessage` — routes to **Vithey AI** module |

### 9. System announcement (`system`)

| Field | Value |
|-------|-------|
| Trigger | `system.announcement`, maintenance, policy updates |
| Copy | Server `title` + `body` (plain text only) |
| Badge | `Icons.campaign` — neutral |
| Destination | In-app WebView, settings, or snackbar — from `destination.routeName` |

## FCM `data` payload (minimum)

```json
{
  "notification_id": "uuid",
  "type": "CHAT",
  "event": "chat.message.sent",
  "reference_type": "CONVERSATION",
  "reference_id": "uuid",
  "actor_id": "uuid",
  "actor_name": "Kimheang",

  "body": "Kimheang sent you a message."

```

Optional: `post_id`, `comment_id`, `job_post_id`, `application_id`, `payment_id`, `ai_thread_id`, `dedupe_key`.

## `NotificationRouter` (Flutter)

```dart
class NotificationRouter {
  static void openFromNotification(AppNotification n) {
    switch (n.type) {
      case NotificationType.postLike:
      case NotificationType.postComment:
      case NotificationType.postMention:
      case NotificationType.postShare:
        Get.toNamed(AppRoutes.postDetail, arguments: n.destination.postId);
        break;
      case NotificationType.newFollower:
        Get.toNamed(AppRoutes.profile, arguments: ProfileArgs(userId: n.destination.userId!));
        break;
      case NotificationType.chatMessage:
        Get.toNamed(AppRoutes.chatDetail, arguments: ChatDetailArgs(conversationId: n.destination.conversationId!));
        break;
      case NotificationType.aiAssistantResponse:
        Get.toNamed(AppRoutes.chatbot, arguments: ChatbotArgs(threadId: n.destination.aiThreadId));
        break;
      case NotificationType.paymentDue:
      case NotificationType.paymentOverdue:
        Get.toNamed(AppRoutes.finance);
        break;
      // ... remaining types
      default:
        Get.snackbar('Vithey', n.displayText);
    }
  }

  static void openFromFcmData(Map<String, dynamic> data) {
    final notification = AppNotification.fromFcmData(data);
    if (notification == null) return;
    WidgetsBinding.instance.addPostFrameCallback((_) {
      openFromNotification(notification);
    });
  }
}
```

## Row display text builder

Prefer structured builder over raw server `body`:

```dart
String buildDisplayText(AppNotification n) {
  final actor = n.actor?.fullName ?? 'Someone';
  return switch (n.type) {
    NotificationType.postLike => '$actor liked your post.',
    NotificationType.postComment => '$actor commented on your post.',
    NotificationType.postShare => '$actor shared your post.',
    NotificationType.newFollower => '$actor started following you.',
    NotificationType.chatMessage => '$actor sent you a message.',
    NotificationType.aiAssistantResponse => 'Vithey AI finished your request.',
    _ => n.body.isNotEmpty ? n.body : n.title,
  };
}
```

## Social feed → notification flow

```text
User A likes User B's post
    → content-service publishes reaction.added
    → notification-service consumes event
    → INSERT notification row (recipient = B)
    → Firebase Admin SDK send to B's device tokens
    → Flutter FcmService receives
    → upsert inbox + show local notification
    → User B taps → PostDetail(postId)
```

## Chat → notification flow (parallel to WebSocket)

```text
User A sends chat message
    → chat-service persists + STOMP to B (if online in app)
    → RabbitMQ chat.message.sent
    → notification-service → FCM (if B backgrounded or not in thread)
    → Flutter: tray notification OR in-app upsert if foreground
    → Tap → ChatDetail(conversationId)
```

## Acceptance criteria

- [ ] All 9 types have icon, copy template, and typed destination
- [ ] Backend broad types normalized with event subtypes
- [ ] Share notifies only public reshares
- [ ] Job notifications never expose CV in payload
- [ ] AI routes to chatbot module, not private chat
- [ ] `NotificationRouter` used from inbox row tap and FCM tap
- [ ] Unknown type falls back to `system` — never crashes list
