## Goal

Show a verified student their outstanding balance, due timing, paycheck total, payment/transaction history, and secure invoice detail/download. Users who are not verified must be routed to the appropriate verification state instead of a broken Finance screen.

**v1 UI focus (from `update.md`):** redesign the balance card, add Total Paycheck, and simplify transaction-row chrome. Do **not** change business logic unless required to support the new labels.

## Access gate

Unchanged from v0:

1. Read auth/user state from session and `GET /api/v1/auth/me` when needed.
2. Route by verification state:
   - `NOT_SUBMITTED` → student verification form
   - `PENDING` → verification-status screen
   - `REJECTED` → verification-status with retry guidance
   - `VERIFIED` / role `STUDENT` → Finance Home
3. Finance-service still enforces `STUDENT` server-side; UI gating is not authorization.
4. On finance `403`, refresh verification/role once. Do not loop.
5. Newly verified students may briefly wait for provisioning — show **Setting up your finance account…** with Retry.

### 2. Balance card (redesign — replace v0 summary card content)

Remove the previous balance-card layout entirely (old upper **Due in** badge, **Next Due Date**, and **Status** split). Rebuild to match `Finace See All.png` + `update.md`.

#### Layout (top → bottom)

```text
┌──────────────────────────────────────────────┐
│  Outstanding Balance              ┌────────┐ │
│  $1,200                           │ wallet │ │
│  [ Due in 14 Days ]               └────────┘ │
│                                              │
│  [              Pay Now                    ] │
└──────────────────────────────────────────────┘
```

| Zone | Content | Spec |
|---|---|---|
| Top row — left | Label **Outstanding Balance** (small, white, muted on teal) | Money owed; not “Total Paycheck” |
| Top row — left | Amount under label, large bold white | e.g. `$1,200` — currency-format from server; never hard-code fixtures |
| Top row — right | Wallet illustration | Asset: `screen image/finance/wallet icon.png` (blue wallet, gold snap, green bills). Align with the **label + amount** block (upper half), not the Pay Now button. Keep aspect ratio; ~56–72 logical px tall guide; do not stretch or crop into a circle |
| Below amount | **Due in** pill | **Under the balance**, left-aligned under the amount column (not top-right of the card). White/light pill, teal text, e.g. `Due in 14 Days` |
| Bottom | **Pay Now** | Full-width white rounded button, teal label; sits below Due pill with clear gap; does not share a row with the wallet |

#### Visual style

- Rounded teal card; prefer a soft **teal → slightly deeper teal** vertical gradient as in the mock (brand primary family), not a flat gray card.
- Comfortable internal padding (~16–20); amount is the hero number.
- Wallet must not overlap Due pill or Pay Now.
- Light/dark: keep brand teal card; Due pill + Pay Now stay high-contrast on the card.

#### Behavior

- **Pay Now** — open next unpaid payment / existing pay or invoice flow. Do not invent a payment gateway. If only invoice preview exists, open that unpaid `payment_id`.
- Totals use decimal/minor-unit money types; never binary floats.
- Compatible currencies only; never sum USD + KHR directly.
- Days remaining from server due dates (campus/user timezone). Badge copy must match the computed window (mock shows 14 days; do not mislabel a 7-day alert API as 14 without computing from due dates).

#### Explicit removals vs v0 card

- No top-right Due badge.
- No bottom **Next Due Date** / **Status** two-column footer.
- No “TOTAL DUE / TOTAL PAYABLE / TOTAL PAYCHECK” as the primary card title — primary title is **Outstanding Balance**.

### 5. Transaction row (UI chrome update)

Keep overall row structure (icon · name/date · amount/status). Apply `update.md` chrome rules:

**Remove:**

- Filled background behind the transaction **icon** (no gray/colored circular plate behind the glyph beyond what the status icon itself needs — prefer the mock’s status glyph treatment without an extra filled tile chrome).
- Filled background / pill plate behind the transaction **status** text — status is colored text only (e.g. orange **Pending**, green **Paid**), not a filled chip.

**Keep:**

- Fee name bold; date muted below.
- Amount bold on the right; status text under amount.
- Row tap → invoice/payment preview for that `payment_id`.
- Rounded row container / light border as in the mock if present; do not reintroduce icon/status fill plates.

Status mapping (unchanged logic):

| Backend | Display | Style |
|---|---|---|
| `PAID` | Paid | Green text (+ green check icon) |
| `UNPAID` | Pending | Orange/warning text (+ clock icon) |
| `OVERDUE` | Overdue | Red/high emphasis |

Use one approved unpaid term throughout; do not call unpaid items completed receipts in a11y copy.
