# 02 - Settings Account Prompt

Build the **Account** settings screen for Vithey App in Flutter, matching:

- `Prompt Frontend/screen image/setting/setting_account.png`

## Quick info

| Field | Value |
|---|---|
| Route | `Routes.SETTING_ACCOUNT` |
| Flutter module | `lib/modules/settings/account/` |
| Backend services | `user-profile-service`, `auth-service`, `file-service` |
| Auth required | Yes |
| Entry point | Settings Home → Account |

## Goal

Show the current user's full profile/account information from `UserProfileModel` and support avatar/profile editing.

## Visual requirements

Match `setting_account.png`:

- White/light background.
- App bar:
  - Back arrow on left.
  - Bold title: **Account**.
  - Thin divider below.
- Use elevated cards with soft shadows to create a floating, pop-up appearance. Each section should feel slightly raised above the background, with rounded corners, subtle depth, and clear separation between sections.
- **Profile header**
  - Centered circular avatar near top.
  - Small teal camera floating button overlapping bottom-right of avatar.
  - Teal **Update Information** action below avatar with pencil icon.
- **Info fields**
  - Grouped into labeled sections (see below).
  - Each field uses a rounded white card with subtle shadow.
  - Primary leading icon + label row on top.
  - Value below (or chip/list for multi-value fields).
  - Empty values show muted placeholder text (e.g. `Not set`).
- Bottom navigation remains visible with **Profile** selected, matching the app shell.

## Controller behavior

- `loadAccount()`:
  - Load cached `UserProfileModel` for instant paint.
  - Fetch `GET /users/me`.
  - Optionally fetch `GET /auth/me` to fill `email` / `phone` if missing from profile.
  - Map response into `UserProfileModel` and expose all display fields to the UI.
- `changeAvatar()`:
  - Open image picker/camera sheet.
  - Upload selected image via `POST /files/upload` with `type=AVATAR`.
  - Save avatar via `PATCH /users/me/avatar`.
  - Update `avatarUrl` in local state immediately from response.
- `openEditInfo()`:
  - Navigate to `Routes.SETTING_EDIT_ACCOUNT` (see `setting_edit_account.md`).
  - Reload profile when edit screen returns with success.

## API

| Method | Path | Notes |
|---|---|---|
| `GET` | `/api/v1/users/me` | Current profile — all profile fields |
| `GET` | `/api/v1/auth/me` | Auth info fallback for `email` / `phone` / `role` |
| `PATCH` | `/api/v1/users/me` | Update editable profile fields |
| `POST` | `/api/v1/files/upload` | Upload avatar with `type=AVATAR` |
| `PATCH` | `/api/v1/users/me/avatar` | Save avatar file/url |

Use `Prompt Frontend/api-intergration/integration-contract.md`.

## Empty/error states

- Avatar missing: show initials fallback or `AppLogo`.
- Nullable string fields missing: show `Not set` in muted text.
- Empty `education` / `skills`: show section with empty-state hint.
- Profile loading: skeleton cards for all sections.
- Profile load error: `AppErrorWidget` with Retry.
- Avatar upload failure: snackbar + keep previous avatar.

## Testing

- Renders avatar and **all** `UserProfileModel` display sections listed above.
- Nullable fields show placeholder when empty.
- Stats show numeric defaults (`0`) correctly.
- Skills render name + proficiency.
- `isStudentVerified` shows verified badge when true.
- Social/portfolio links open externally when tapped.
- `Update Information` opens edit flow with editable fields only.
- Avatar upload sends multipart type `AVATAR`.
- Failed update does not clear current data.
