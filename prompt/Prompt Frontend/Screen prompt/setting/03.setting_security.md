# 03 - Settings Security Prompt

Build the **Security** settings screen for Vithey App in Flutter, matching:

- `Prompt Frontend/screen image/setting/setting_security.png`

## Quick info

| Field | Value |
|---|---|
| Route | `Routes.SETTING_SECURITY` |
| Flutter module | `lib/modules/settings/security/` |
| Backend services | `auth-service`, `user-profile-service` |
| Auth required | Yes |
| Entry point | Settings Home → Security |

## Goal

Let users manage account security: change password, two-factor authentication, biometric login, and active sessions.

## Visual requirements

Match `setting_security.png`, aligned with Settings Home and Privacy screen styling (`01.setting_home.md`, `03.setting_privacy.md`). All colors must come from `Theme.of(context)` / `colorScheme` so the screen looks correct in **both light and dark mode** — never hardcode white, black, or pale-red hex values.

- Theme background (`scaffoldBackgroundColor`), light or dark depending on mode.
- App bar:
  - Back arrow on left.
  - Bold title: **Security**.
  - Thin divider below.
  - Reuse `settings_scaffold.dart`.
- Header section:
  - Title: **Security Settings**
  - Subtitle: **Manage your account security and authentication** in muted `onSurfaceVariant` color.
- Rounded grouped security card (surface color, soft shadow, rounded corners — same card style as the Privacy switch card):
  - **Change Password** row — lock outline icon, subtitle **Update your account password**, trailing chevron. Navigates on tap.
  - **Two-Factor Authentication** row — key outline icon, subtitle **Extra security for your account**, trailing switch.
  - **Biometric Login** row — phone/fingerprint outline icon, subtitle **Use fingerprint or face ID**, trailing switch.
  - Each row:
    - Left outline icon in **primary color** (`Theme.of(context).colorScheme.primary`), size ~22.
    - Bold title, grey/muted subtitle below.
    - Right **compact switch** — same size and component as the **Dark Mode** toggle on Settings Home (`SettingsSwitchTile` / `shad.Switch`). Do **not** use the larger Material `Switch.adaptive`.
    - Row vertical padding ~14px, matching other settings rows.
    - Inset divider between rows (not full-bleed edge-to-edge).
- **Active Sessions** card (surface color, soft shadow, rounded corners):
  - Primary-colored shield icon + bold title: **Active Sessions**.
  - **Current Device** row with device icon, subtitle **Last active: Just now**.
  - Right status label **Active** in primary color.
- Bottom navigation remains visible with **Profile** selected, matching the app shell.

## Controller behavior

- `openChangePassword()` → `Get.toNamed(Routes.SETTING_CHANGE_PASSWORD)`.
- `toggleTwoFactor(bool value)`:
  - If backend supports 2FA, open enrollment/disable flow.
  - If unsupported, show “Two-factor authentication is coming soon” and keep switch off.
- `toggleBiometric(bool value)`:
  - Use local biometric availability check.
  - Store local preference only after successful local auth.
- `loadActiveSessions()`:
  - Use current device local info until backend exposes sessions endpoint.

## API

Current documented API:

| Method | Path | Notes |
|---|---|---|
| `POST` | `/api/v1/auth/logout` | Current-device logout only |

Recommended backend additions for full security features:

| Method | Path | Notes |
|---|---|---|
| `PATCH` | `/api/v1/auth/me/password` | Change current password |
| `GET` | `/api/v1/auth/sessions` | List active sessions |
| `PATCH` | `/api/v1/auth/me/2fa` | Enable/disable 2FA |

Do not implement fake remote session behavior if backend endpoints do not exist.

Use `Prompt Frontend/api-intergration/integration-contract.md`.

## UX rules

- Security toggles must use the **same compact switch size** as Dark Mode on Settings Home — not oversized platform switches.
- Row icons use **primary color**, not grey/muted.
- Every surface, text, and tint color must adapt to theme — verify legibility in dark mode.
- Toggles must not lie about unsupported backend features.
- Keep explanatory text short and readable.

## Security rules

- Never log passwords, tokens, or session IDs.
- Biometric toggle is local app unlock only unless backend supports device binding.

## Testing

- Screen matches reference grouping and copy in light mode, and remains legible with correct tints in dark mode.
- Switch rows use compact toggles matching Settings Home Dark Mode.
- Row icons and Active Sessions shield/status use primary color.
- Change Password row navigates correctly.
- Toggles do not lie about unsupported backend features.
- Active Sessions card renders current device.

## Output

Complete Security screen matching `setting_security.png`, styled consistently with the Privacy screen, fully theme-aware for light and dark mode, with safe behavior for implemented and not-yet-supported security APIs.
