# 03 - Settings Privacy Prompt

Build the **Privacy** settings screen for Vithey App in Flutter, matching:

- `Prompt Frontend/screen image/setting/setting_privacy.png`

## Quick info

| Field | Value |
|---|---|
| Route | `Routes.SETTING_PRIVACY` |
| Flutter module | `lib/modules/settings/privacy/` or `lib/modules/settings/` |
| Backend service | `user-profile-service` |
| Auth required | Yes |

## Goal

Let users control basic privacy preferences and understand data protection.

## Visual requirements

Match `setting_privacy.png`:

- White background.
- App bar:
  - Back arrow.
  - Bold title: **Privacy**.
  - Divider below.
- Header section:
  - Title: **Privacy Settings**
  - Subtitle: **Control how your data is used and shared**
- Rounded grouped card with three switch rows:
  - Profile Visibility
  - Data Sharing
  - Activity Tracking
- Each row:
  - Left grey icon.
  - Bold title.
  - Grey subtitle.
  - Right iOS-style switch.
  - Divider between rows.
- Data Protection information card:
  - Teal shield icon.
  - Title: **Data Protection**
  - Body copy exactly: `Your data is encrypted and securely stored. We never share your personal information with third parties without your consent.`
  - Teal link: **Learn more about our privacy practices →**
- Bottom navigation remains visible with Profile selected.

## Preferences model

```dart
class PrivacySettings {
  final bool profileVisible;
  final bool dataSharing;
  final bool activityTracking;
}
```

If backend settings are nested, store under:

```json
{
  "privacy": {
    "profile_visible": true,
    "data_sharing": false,
    "activity_tracking": false
  }
}
```

## Controller behavior

- `loadPrivacySettings()`:
  - Load local cache first.
  - Fetch `GET /users/me/settings`.
- `toggleProfileVisibility(bool value)`:
  - Optimistically update UI.
  - Persist to `PATCH /users/me/settings`.
  - Roll back on failure.
- `toggleDataSharing(bool value)` and `toggleActivityTracking(bool value)` same behavior.
- `openPrivacyPractices()`:
  - Open in-app article route if available.
  - Otherwise use `url_launcher` to open a configured privacy URL.

## API

| Method | Path | Notes |
|---|---|---|
| `GET` | `/api/v1/users/me/settings` | Load privacy preferences |
| `PATCH` | `/api/v1/users/me/settings` | Save changed preference |

Use `Prompt Frontend/api-intergration/integration-contract.md`.

## UX rules

- Switch changes are optimistic but must roll back on API failure.
- Do not claim data is shared when toggles are off.
- Keep explanatory text short and readable.
- If a privacy preference is unsupported by backend, hide it behind local-only flag or disable with clear copy.

## Testing

- Screen matches reference grouping and copy.
- Each switch updates controller state.
- Failed API update rolls back only the affected switch.
- Data Protection link has a real action or is hidden.

## Output

Complete Privacy settings screen matching `setting_privacy.png`, with persistent settings through `user-profile-service`.
