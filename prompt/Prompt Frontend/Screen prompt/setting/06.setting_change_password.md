# 06 - Setting Change Password Prompt

Build the **Change Password** settings screen for Vithey App in Flutter, matching:

- `Prompt Frontend/screen image/setting/setting_change_password.png`

## Quick info

| Field | Value |
|---|---|
| Route | `Routes.SETTING_CHANGE_PASSWORD` |
| Flutter module | `lib/modules/settings/security/` or `lib/modules/settings/change_password/` |
| Backend service | `auth-service` |
| Auth required | Yes |

## Goal

Allow the signed-in user to update their password securely.

## Visual requirements

Match `setting_change_password.png`:

- White background.
- App bar:
  - Back arrow.
  - Bold title: **Change Password**
  - Divider below.
- Header:
  - Centered circular pale-teal icon container.
  - Lock icon in teal.
  - Title: **Update your password**
  - Subtitle: **Choose a strong password to keep your account safe**
- Form fields with labels and placeholders:
  - Current Password — placeholder: **Enter current password**
  - New Password — placeholder: **Enter new password**
  - Confirm New Password — placeholder: **Repeat new password**
- Each field:
  - Rounded input.
  - Leading lock icon.
  - Eye icon toggle on right:
    - While the value is hidden, show an **open eye** icon — tapping it reveals the value.
    - While the value is visible, show a **closed eye** (eye-off) icon — tapping it hides the value again.
    - Each field toggles independently.
- Requirements card:
  - Title: **Requirements**
  - Dots for each requirement.
  - At least 8 characters.
  - One uppercase letter.
  - One number.
  - One special character.
- CTA:
  - Full-width teal rounded button: **Update Password**
  - Label must be **centered** horizontally and vertically within the button.
  - Button is **disabled** until all validation rules pass (see Validation).
- Bottom navigation remains visible with Profile selected.

## Validation

| Field | Rule |
|---|---|
| Current Password | Required |
| New Password | Required, min 8, uppercase, number, special char |
| Confirm New Password | Must match new password |

Password requirements should update live:

- Grey dot when unmet.
- Teal/green dot when met.
- **Update Password is disabled** until every requirement is met, current password is entered, and confirm matches — invalid input must never be submittable.

## API

The current public contract includes reset-password for logged-out users. This screen needs an authenticated change-password endpoint.

Recommended backend contract:

| Method | Path | Request | Notes |
|---|---|---|---|
| `PATCH` | `/api/v1/auth/me/password` | `{ "current_password": "...", "new_password": "..." }` | Authenticated password update |

If backend does not have this endpoint yet:

- Create `AuthRepository.changePassword()` with the endpoint above.
- Keep the API path centralized in `ApiEndpoints`.
- Do not implement fake success.
- If API returns `404`, show **Password change is not available yet.**

Use `Prompt Frontend/api-intergration/integration-contract.md`.

## Security rules

- Never log password values.
- Do not store password values.
- Dispose controllers.
- Disable screenshots only if product requires high security; otherwise avoid platform-specific complexity.
- Prevent double submission while loading.

## Testing

- Each field shows its placeholder text when empty.
- Password requirement dots update live.
- Confirm password mismatch blocks submit; button stays disabled until all rules pass.
- Eye toggles work independently: open eye reveals the value, closed eye hides it.
- Update Password label is centered in the button.
- Successful API call routes back.
- API failure shows error and does not clear new/confirm unexpectedly.

Complete Change Password screen matching `setting_change_password.png`, with secure validation and repository/API wiring.
