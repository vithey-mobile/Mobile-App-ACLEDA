# 03 - Chat Participant Profile Prompt

Build the chat-contact profile shown in `Prompt Frontend/screen image/chat/chat_profile.png`.

This is conversation-specific participant information and shared-media management. The full social profile remains in `../profile/`.

## Route/authorization

- `Routes.CHAT_PROFILE` with typed `ChatProfileArgs(conversationId, participantId)`.
- Server verifies current user is a conversation participant.
- Stable IDs are authoritative; never trust display name/avatar alone.

## Layout

### Header

- Back arrow, centered **Profile**, overflow menu.
- Large circular avatar with presence dot only when truthful.
- Bold participant name and online/last-seen status.

### Quick actions

Four rounded actions matching reference:

- **Message** → returns/opens active thread.
- **Call**.
- **Video**.
- **Mute/Unmute**.

Current chat backend supports text only and no call/video/mute contract. Feature-gate these actions; never show fake ringing/connected state. If unavailable, hide rather than dead-button.

### Info card

- Phone only if explicit visibility/relationship policy permits it.
- Public bio/headline.
- Location/other fields only from privacy-aware profile response.
- Current user must never retrieve hidden auth phone/email by bypassing profile service.

### Shared content tabs

- **Media**: shared images.
- **Videos**: shared videos.
- **Files**: shared documents.
- Grid/list is paginated and scoped to this conversation.
- Tap opens secure preview by message/attachment ID.
- Reference grid is fixture media only.

Current Message model is text-only. Hide shared-content tabs or show truthful empty state until attachment schema/upload/access endpoints exist.

## Overflow safety actions

- View Full Profile.
- Mute/Unmute when supported.
- Block user — confirmation.
- Report user — reason form + confirmation.

Blocking updates conversation to BLOCKED, disables messaging, and returns safely. Reporting does not automatically block unless user explicitly chooses it.

## Presence/privacy

- Presence is server-derived, ephemeral, and privacy-aware.
- Respect users who hide last seen/phone.
- Do not infer online status from app-open time/client timers.
- Shared media/files remain private to authorized participants and use short-lived access.
- Clear cached private previews on logout/account switch.

## Required backend extensions

- Presence/last-seen visibility.
- Per-conversation mute preference.
- Voice/video calling/signaling if enabled.
- Attachment message schema and paginated conversation media/files.
- Privacy-aware phone/bio projection for chat contacts.

Do not invent production endpoints or show functional-looking unsupported actions.

## States

- Profile skeleton, unavailable/blocked participant, offline stale data.
- Media tab loading/empty/pagination/error.
- Secure preview loading/expired access.
- Block/report/mute mutation state and rollback.

## Accessibility/testing

- Label avatar/presence, name, actions, info, tabs, media, overflow safety actions.
- Do not rely on green dot alone for online state.
- Minimum `44 × 44`; support `320 px`, large text, long bio, tablet grid.
- Verify privacy-hidden fields never render.
- Verify unsupported Call/Video/Mute/media are hidden/feature-gated.
- Verify Block/Report confirmation and authorization.

## Output

Deliver a privacy-aware chat participant profile with safe actions, conversation-scoped shared content, and feature-gated calling/media capabilities.
