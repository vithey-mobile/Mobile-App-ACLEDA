# 01 - Chat Conversation List Prompt

Build the private conversation list shown in `Prompt Frontend/screen image/chat/listchat.png`.

## Quick info

- Route: `Routes.CHAT`.
- Backend: `chat-service`.
- Auth required.
- Opens from bottom navigation with Chat active.

## Layout

### App bar

- Vithey logo and **Vithey** at left.
- Search action at right.
- White safe-area-aware surface.

### Add Chat / recent contacts row

- Horizontal circular avatar row below app bar.
- First item: teal outlined plus and **Add Chat**.
- Following items are recent/eligible contacts with name labels.
- Tap Add Chat opens debounced user search; selecting a user opens an existing conversation or explicit initial-message request composer.
- Never send a default message automatically.

### Messages list

- Heading **Messages**.
- Paginated newest-activity-first conversation rows:
  - Avatar.
  - Other participant name.
  - Last-message preview or **Typing…** only when truthful.
  - Relative time.
  - Teal unread count badge.
  - Own last-message read/delivered ticks when appropriate.
- Tap opens `02.chat_message.md` with stable conversation ID.
- Long press/overflow offers Mute, Block, Report only when supported; destructive actions confirm.

### Bottom navigation

- Home, Chatbot, raised Create, Chat active, Profile.
- Preserve conversation list state across tab changes.

## Message requests

- Load `GET /api/v1/message-requests` separately.
- Show pending request count/section or entry without mixing PENDING conversations into ACTIVE chats deceptively.
- Request card displays requester and initial message.
- Accept → `/conversations/{id}/accept`, moves into active list.
- Decline → confirmation then `/decline`, removes request.
- Block/Report follow safety flow.
- Duplicate request `409` reconciles to existing request/conversation.

## Real-time list updates

- Subscribe to authenticated STOMP `/user/queue/messages` through one shared chat connection.
- Incoming message upserts/moves its conversation to top and increments unread only when thread is not actively visible/read.
- Outgoing/receipt events reconcile preview/ticks.
- De-duplicate REST/WebSocket messages by message ID.
- Typing/presence require explicit ephemeral backend events; do not fake with timers.

## API

- `GET /api/v1/conversations` paginated.
- `GET /api/v1/message-requests`.
- `POST /api/v1/conversations/request`.
- `POST /api/v1/conversations/{id}/accept|decline|block`.
- `POST /api/v1/users/{userId}/report`.

Current conversation response must include participant summary, last message, unread count, updated time, and status to render efficiently. Avoid per-row profile/message requests.

## States

- Initial skeleton, empty **No messages yet**, refresh, pagination/footer retry.
- Search loading/empty/error.
- Message request mutation states.
- Offline cached list with stale indicator; do not queue requests silently.
- Blocked/declined conversations removed or rendered per policy.

## Accessibility/testing

- Label conversation, unread count, message status, Add Chat, requests, search, and nav.
- Minimum `44 × 44` targets; large text/long previews truncate safely.
- Test pagination/dedupe, real-time reorder, active-thread unread rules, request accept/decline/block/report, search, account-switch cache clearing.

## Output

Deliver a responsive real-time conversation list with Add Chat, requests, unread state, and safe routing.
