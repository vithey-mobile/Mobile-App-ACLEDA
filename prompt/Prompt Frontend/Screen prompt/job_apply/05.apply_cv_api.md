# 05 — Apply CV API, Eligibility & Home Sync

Backend contracts, privacy rules, and card-state synchronization for the job apply flow.

## API endpoints

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/api/v1/posts/{jobPostId}` | Load job post + `jobMeta` |
| `GET` | `/api/v1/job-applications` | Current user's applications (filter by `job_post_id`) |
| `GET` | `/api/v1/job-applications/{applicationId}` | Status screen detail + timeline fields |
| `GET` | `/api/v1/users/me/cv` | Saved default CV metadata |
| `POST` | `/api/v1/files/upload` | Private CV upload (`type=CV`, multipart) |
| `PUT` | `/api/v1/users/me/cv` | Set default CV (explicit consent only) |
| `POST` | `/api/v1/job-applications` | Create application |

### Create application request

```json
{
  "job_post_id": "uuid",
  "cv_file_id": "uuid",
  "position_id": "uuid",
  "application_note": "Optional cover message"
}
```

`position_id` and `application_note` are feature-gated — include only when career-service documents them.

### Create application response (`201`)

```json
{
  "application_id": "uuid",
  "job_post_id": "uuid",
  "cv_file_id": "uuid",
  "cv_file_name": "Heng_Liza_CV.pdf",
  "status": "PENDING",
  "applied_at": "2026-07-07T09:14:00Z",
  "timeline": {
    "submitted_at": "2026-07-07T09:14:00Z",
    "reviewed_at": null,
    "decided_at": null
  },
  "reviewer_note": null
}
```

## File upload policy

| Rule | Value |
|------|-------|
| MIME (current) | `application/pdf`, `application/msword`, DOCX |
| Max size | `10 MB` unless backend publishes other |
| Storage | Private `CV` bucket — never `POSTER` |
| Validation | Client early check; server authoritative + malware scan |

Display string builder example:

```dart
String cvPolicyLabel(AppFilePolicy policy) =>
  '${policy.extensionsLabel} (max. ${policy.maxMb} MB)';
```

## CV selection modes

| Mode | Upload on submit? | Updates default CV? |
|------|-------------------|---------------------|
| Use saved CV | No | No |
| Application-only file | Yes | No |
| Update default CV | Yes | Yes — after explicit **Use as my default CV** toggle on step 2 |

## Eligibility checks (client + server)

Before step 1 Continue and before Submit:

- Post exists, type `JOB`, lifecycle `OPEN`
- Deadline not passed; application limit not reached (when supported)
- Current user ≠ job author
- No existing application for `(job_post_id, applicant_id)`

| HTTP | Client behavior |
|------|-----------------|
| `409` | Already applied → status screen or Applied card |
| `403` | Not eligible / own job |
| `404` | Job or CV file missing |
| `422` | Closed / full / validation |

## Submission state machine

```text
idle → validating → uploadingCv → applying → success
                      ↓              ↓
                    error ←──────── retry (reuse cv_file_id)
```

Rules:

- Idempotency key per submit attempt
- Upload success + apply failure → retry apply only
- Never delete uploaded CV referenced by application
- Duplicate tap does not start parallel pipeline

## Home / feed card sync

After success, origin must update **only** the matching `jobPostId`:

```dart
class ApplyCvResult {
  final String jobPostId;
  final String applicationId;
  final JobApplicationStatus status;
}
```

Consumption in `HomeController` / `PostDetailController`:

```dart
void onApplyCvResult(ApplyCvResult result) {
  updateJobCardApplicationState(
    jobPostId: result.jobPostId,
    state: JobCardApplicationState.applied,
    applicationId: result.applicationId,
  );
}
```

Feed DTO should include `viewer_application_status` or `has_applied` to avoid N+1 — see contract gaps below.

## Privacy & security

- CVs visible only to applicant and authorized job owner/reviewer
- Short-lived signed URLs for preview; never embed in notifications
- Do not parse poster QR codes for application routing
- Clear local temp files on logout
- Audit reviewer CV access server-side
