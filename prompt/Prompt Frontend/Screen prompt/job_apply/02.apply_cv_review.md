## Submit Application button

| State | Label / behavior |
|-------|------------------|
| Ready | **Submit Application** — full-width teal `CustomButton` |
| Uploading CV | **Uploading CV…** — disabled, show progress |
| Submitting | **Submitting application…** — disabled |
| Error | Re-enable with Retry path per `05.apply_cv_api.md` |

Pipeline (guarded state machine):

```text
validating → uploadingCv? → applying → success | error
```

- **Saved CV:** skip upload; `POST /job-applications`
- **New file:** `POST /files/upload` (`type=CV`) then `POST /job-applications`
- Use idempotency key; never parallel uploads on double-tap
- On upload success + apply failure: retain `cv_file_id` for retry

Success navigates to [`03.apply_success.md`](03.apply_success.md) with:

```dart
ApplySuccessArgs(
  applicationId: response.applicationId,
  jobPostId: jobPostId,
  jobTitle: jobMeta.title,
)
```

Return `ApplyCvResult` to origin when user finishes success screen.

## Back link

Centered below primary button:

- Teal **← Back** text button
- Returns to step 1 (`currentStep = 0`) without losing selected file or cover note
- During active upload/submit: disabled or confirm cancel

## Error handling

| Error | UI |
|-------|-----|
| Upload failed | Inline under file card; **Retry** on Submit |
| Apply `409` | Treat as already applied; navigate to status or back with Applied state |
| Apply `422` / job closed | Banner — job no longer accepting |
| `401` | Global auth refresh |
| Network | `AppErrorWidget` with Retry |

Never show raw API bodies, signed URLs, or stack traces.
