# 01 - Vithey AI Chatbot Home Prompt

Build the ChatGPT-style Vithey AI screen shell and multi-session orchestration.

## Visual reference

- `Prompt Frontend/screen image/chatbot/chatbot-home.png`.

## Route and services

- Route: `Routes.CHATBOT`.
- Module: `lib/modules/chatbot/`.
- Backend: `ai-service`.
- Auth required.
- Topics: CV, JOB, INTERVIEW, STUDENT, FINANCE.

## Layout

- Safe white/light screen.
- Left circular hamburger opens `02.chatbot_list_history.md`.
- Teal **Vithey AI** title pill.
- Right action must have a documented semantic purpose; recommended New Chat.
- Lazy message list.
- Sticky composer from `03.chatbot_input.md`.

## Empty state

- Preserve the spacious reference layout.
- Show 3–5 useful topic-aware starter prompts.
- Replace repeated fixture **Follow Foot ball** with prompts such as CV help, interview practice, job application guidance, and student support.
- Tap fills/focuses the composer or sends consistently; recommended fill so users can edit.

## Session behavior

- New draft session remains local until first successful message if server creates sessions through `/ai/chat`.
- First response returns/adopts `session_id` exactly once.
- Selecting history loads that owned session and closes drawer.
- Preserve per-session draft and scroll position during the app session.
- Cancel/ignore stale requests when switching quickly.
- Clear session caches/drafts on logout/account switch.

## Message list

- User messages align right in compact bubbles.
- Assistant messages align left/wide with Vithey mark and use `04.chatbot_response.md`.
- Lazy-load older messages upward and preserve viewport when prepending.
- Auto-scroll only when user is near bottom; otherwise show **Jump to latest**.
- Group consecutive roles where useful while preserving semantic author labels.

## Topic handling

- User selects topic for a new session or backend auto-routing must return/document it.
- One authoritative topic per session unless switching is explicitly supported.
- Finance assistant never fabricates balances/private transactions.

## API

- `POST /api/v1/ai/chat`.
- `GET /api/v1/ai/sessions`.
- `GET /api/v1/ai/sessions/{id}/messages`.
- `DELETE /api/v1/ai/sessions/{id}`.

Advanced session mutations, streaming, and attachments are defined in sibling prompts and feature-gated until supported.

## Controller responsibilities

- `newChat()`.
- `selectSession(sessionId)`.
- `loadMessages()` / `loadOlderMessages()`.
- Coordinate input Send/Stop and assistant stream state.
- `selectTopic()`.
- Maintain independent session/message/draft/stream states.
- Handle offline, 401, 404 ownership-safe session removal, 429 cooldown, and provider 502.

## Security/privacy

- Enforce session ownership server-side on every operation.
- Never leak whether another user's session exists.
- Do not send passwords, tokens, full payment data, verification documents, or unrelated chats to the AI provider.
- Avoid logging full prompts/responses unless documented redaction/consent exists.
- Show concise AI accuracy disclaimer where appropriate.

  widgets/

## Testing and acceptance criteria

- Matches chatbot-home reference shell/empty state.
- New chat creates no empty server session.
- Session switch ignores stale responses and restores drafts/scroll.
- Older-message pagination and Jump to latest work.
- Topic and auth ownership are correct.
- Small screens, keyboard, large text, long conversations, offline/rate-limit/provider errors remain usable.

## Output

Deliver the secure multi-session Vithey AI shell composed from the History, Input, and Response prompts.
