# 01 - Profile Home and Owner/Visitor Shell Prompt

Build the shared Vithey Profile shell used for the authenticated user's profile and another user's public profile.

## Visual reference

- `Prompt Frontend/screen image/profile/profile_home.png`.

Detailed tabs and job/CV flows are owned by the sibling prompts listed in `README.md`.

## Routes and identity

- Route: `Routes.PROFILE` with typed `ProfileArgs(userId)`.
- Bottom-nav Profile supplies the authenticated user ID.
- Avatars/names elsewhere supply a target user ID.
- Compute `isOwnProfile = targetUserId == authSession.userId`; never trust a caller-supplied owner flag.

## Layout

1. Shared app bar: hamburger, centered **Vithey**, notification bell.
2. Cover/banner with neutral fallback.
3. Large circular avatar overlapping cover.
4. Follower, following, and post counts.
5. Full name and collapsed/expandable bio.
6. Context-aware action row.
7. Pinned tabs: About, Posters, Videos, Jobs.
8. Shared bottom navigation with Profile active.

## Owner versus visitor actions

Another user's profile:

- **Follow** / **Following**.
- Teal **Message**.

Own profile:

- Never show Follow.
- Never show Message-to-self.
- Show **Edit Profile** and optional Settings, or leave the action area clear.

Blocked/private/unavailable relationships follow server policy and never leak protected data.

## Follow

- Initial relationship and counts come from authoritative profile/relationship data.
- Optimistic POST follow / DELETE unfollow with rollback.
- Update the user's relationship/count across Profile and Home caches.
- Prevent rapid duplicates and counts below zero.
- Server rejects self-follow; UI hides it.

## Message

- Existing ACTIVE conversation → Chat Detail.
- Existing PENDING request → pending/request state.
- No conversation → explicit initial-message composer, then `/conversations/request`.
- Tapping Message never silently sends default text.
- Handle duplicate request, decline, block, and self-message safely.

## Tabs

- About → `02.profile.about.md`.
- Posters → `03.profile_poster.md`.
- Videos → `profile_video.md`.
- Jobs → `profile_job.md`.

Lazy-load a tab on first selection and preserve its data/scroll position. One tab error never blanks the shell.

## Required profile contract

Current profile response needs extensions for:

- Follower/following/post counts.
- `is_following`/relationship state.
- Optional cover image.
- Privacy-aware extended fields.
- Efficient existing-conversation lookup.

Avoid one request per statistic/action when an aggregate response can provide it.

## Controller

- `loadProfile(userId)` / `refreshProfile()`.
- `toggleFollow()`.
- `startMessage()`.
- `selectTab()`.
- Maintain per-tab state and ignore stale results after rapid user switching.
- Clear private/user-scoped caches on logout/account switch.

## Accessibility and responsive behavior

- Label cover/avatar, stats, action state, tabs, notification/menu, and bottom nav.
- Minimum `44 × 44` targets.
- Support `320 px`, long names/bios, large text, screen readers, and tablets with max width.
- Do not use color alone for relationship/tab state.

## Testing and acceptance criteria

- Matches `profile_home.png` shell/header/stats/tabs.
- Visitor shows Follow and Message.
- Owner never shows either; owner actions are safe.
- Follow rolls back correctly and syncs globally.
- Message opens existing chat or explicit request composer.
- Tab state/scroll survives switching and user navigation without leakage.

## Output

Deliver one responsive Profile shell with strict owner/visitor behavior and modular tab composition.
