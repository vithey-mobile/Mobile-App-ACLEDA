# 02 - Private Chat Message Thread Prompt

Build the real-time message thread shown in `Prompt Frontend/screen image/chat/chatuser.png`.

## Route

- `Routes.CHAT_DETAIL` with typed `ChatDetailArgs(conversationId)`.
- Server verifies participant ownership and ACTIVE status.

## Header

- Back arrow.
- Participant avatar, name, and truthful **Active Now/last seen** only when presence contract exists.
- Search-in-conversation icon when implemented.
- Tap participant header opens `03.chat_profile.md`.

## Message list

- Newest messages at bottom; load older messages upward without viewport jump.
- Own bubbles right in teal; other bubbles left in white/light surface with avatar grouping.
- Timestamps and date separators.
- Own status:
  - SENT: one tick.
  - DELIVERED: double tick.
  - READ: highlighted double tick/Seen.
- Group nearby messages while retaining semantic sender labels.
- Preserve scroll; show Jump to latest/new-message chip when user reads older content.

## Composer

- Rounded pinned input above keyboard/safe area.
- Correct production placeholder: **Write a message…** (reference says Write comment).
- Teal circular Send action.
- Auto-grow multiline upward, then internal scroll.
- Send enabled for non-empty trimmed text.
- Current backend is text-only; hide attachment/camera/voice actions until contracts exist.

## Send lifecycle

1. Generate client message/idempotency ID.
2. Insert optimistic own message as sending.
3. POST or STOMP send `{conversation_id, text}`.
4. Reconcile server `message_id`, timestamp, SENT status.
5. Failure retains text with Retry/Delete; retry does not duplicate.

Reject sending in PENDING/BLOCKED/DECLINED state with clear UI. Never allow self-message.

## WebSocket and ordering

- Connect through gateway `/ws`/documented `/ws/chat` with JWT handshake.
- Subscribe once to `/user/queue/messages` and filter/upsert by conversation ID.
- Send through `/app/chat.send` only when connection/contract supports it; REST fallback remains explicit.
- De-duplicate REST/WS echo by message ID/client ID.
- Order by server timestamp plus stable tie-breaker; never trust device clock alone.
- Reconnect with backoff, app lifecycle awareness, and REST gap fill.

## Read receipts

- Mark incoming visible messages read when screen is foreground and message is actually presented.
- PATCH `/api/v1/messages/{id}/read` efficiently/batched when contract permits.
- Reconcile list unread count to zero only for successfully/read-visible messages.
- Do not mark read merely because a push arrived.

## Typing and presence

- Typing indicator and Active Now from ephemeral server presence/typing events.
- Throttle typing events and auto-expire server state.
- Current contract lacks these events; hide rather than fake.

## Search

- Header search opens local/server conversation search when documented.
- Highlight matches and navigate between results without losing scroll.
- Do not load entire unbounded history merely to search.

## Safety

- Header/overflow: View Profile, Mute, Block, Report.
- Block and Report require confirmation/reason flow and server authorization.
- Blocking disables composer and future delivery.
- Do not expose deleted/blocked participant private info.

## API

- `GET /api/v1/conversations/{id}/messages` paginated.
- `POST /api/v1/conversations/{id}/messages`.
- `PATCH /api/v1/messages/{id}/read`.
- `POST /api/v1/conversations/{id}/block`.
- `POST /api/v1/users/{userId}/report`.

Required extensions for full reference: client message ID/idempotency, typing/presence, mute, search, attachment/media metadata, deletion/edit/reaction if later shown.

## States/testing

- Initial/older-page loading, empty, offline/reconnecting, send failure/retry, blocked/pending, deleted message safe fallback.
- Test ordering/dedupe, REST/WS echo, reconnect gap fill, read rules, optimistic send, pagination anchoring, active-thread unread, keyboard/large text.

## Output

Deliver a secure, real-time text conversation with correct bubble layout, statuses, read receipts, optimistic sending, and lifecycle-safe WebSocket behavior.
