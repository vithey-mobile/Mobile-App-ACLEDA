# 04 - Finance Invoice Detail Prompt

Build the secure invoice/payment-detail surface opened from a Finance payment row.

## Visual reference

- `Prompt Frontend/screen image/finance/preview invoice.png`.

## Route/entry

- Use a large rounded modal bottom sheet or `Routes.PAYMENT_INVOICE` detail surface.
- Input is a typed `PaymentInvoiceArgs(paymentId)`.
- Never authorize or fetch by list index, title, amount, or visible transaction reference.
- Closing returns to the same Finance list position.

## Layout

- Top drag handle and circular close action.
- Large fee title, e.g. **Tuition Fee**.
- Transaction/invoice reference below.
- Light tinted status/date panel:
  - Status label and colored pill.
  - Relevant paid/due date with explicit label.
- **BREAKDOWN**:
  - Base Amount.
  - Processing Fee.
  - Late Charges.
  - Divider.
  - Large authoritative **Total Due** or **Total Paid** according to state.
- Full-width blue **Download PDF Invoice** action with icon.

## Data rules

- Load owned payment detail using `GET /api/v1/payments/{paymentId}`.
- All breakdown values come from server response; never guess fees from the list amount.
- Represent money in minor units/decimal with currency code, never binary floating point.
- Verify `base + processing + late = total`; display authoritative total on discrepancy and report telemetry.
- Do not sum incompatible currencies.
- Paid items distinguish amount paid from remaining due.
- Format currencies/dates by locale and intended timezone.

## PDF invoice

- Use a documented authenticated invoice endpoint or private file ID.
- Ownership is checked server-side.
- Show progress, cancellation, retry, success, and safe open/share/save behavior.
- Use server-provided safe filename and MIME.
- Prefer authenticated bytes or short-lived signed URL; never permanent public URL.
- Never construct an “official” invoice from screenshot/client text.
- Do not log invoice reference, URL, amount, student ID, or file contents.

## Backend contract additions

Current finance API lacks fields required by the reference. Define:

- Transaction/invoice reference.
- Base/processing/late breakdown and authoritative total.
- Paid date versus due date semantics.
- Invoice PDF file/endpoint and authorization.
- Safe filename/MIME/size.
- Whether unpaid items have preview invoices.

Suggested model:

```dart
class PaymentInvoice {
  final String paymentId;
  final String invoiceReference;
  final String feeName;
  final PaymentStatus status;
  final Money baseAmount;
  final Money processingFee;
  final Money lateCharges;
  final Money total;
  final DateTime? dueAt;
  final DateTime? paidAt;
  final String? invoiceFileId;
}
```

## States

- Detail skeleton.
- Loaded.
- Not found/no longer available.
- Ownership forbidden without leaking another student's record.
- Partial/malformed breakdown safe fallback.
- Download progress/cancel/failure/retry.
- Offline cached metadata may display as stale, but PDF requires valid authorization.

## Accessibility/responsive behavior

- Label close, title/reference, status/date, every breakdown row, total, and download progress/action.
- Trap focus while modal is open and restore to originating payment row.
- Minimum `44 × 44` targets.
- Support `320 px`, large text, long fee names/references, and tablets.
- Status is not communicated by color alone.

## Architecture

```text
lib/modules/finance/widgets/
  invoice_preview_sheet.dart
  invoice_breakdown.dart
  invoice_download_button.dart

lib/data/models/payment_invoice_model.dart
```

## Testing and acceptance criteria

- Matches `preview invoice.png` hierarchy and uses exact selected payment ID.
- Breakdown/total use authoritative server values and correct currency precision.
- Paid/unpaid/overdue date and total labels are truthful.
- Download is authenticated, retryable, cancellable, and private.
- Closing preserves Finance Home state.
- Missing/forbidden/offline/large-text states remain safe and usable.

## Output

Deliver a private, accurate invoice-detail and PDF-download experience separated cleanly from Finance Home.
