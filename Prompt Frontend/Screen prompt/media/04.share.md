# 04 - Post Share Type Prompt

Build the reusable Share action used by Poster, Video, and Job cards.

## Visual reference

- `Prompt Frontend/screen image/home/share type.png`.

## Goal

Tapping Share opens a compact sheet that slides from the bottom upward and offers two distinct actions: publicly reshare the post or save it privately.

## Entry contract

```dart
openShareTypes(String postId)
```

- Use stable post ID, never list index/media URL.
- Stop underlying card navigation.
- Preserve Home scroll position.

## Sheet presentation

- White content-driven modal anchored to the bottom.
- Large rounded top corners and centered drag handle.
- Dimmed barrier, safe-area padding, swipe/outside/Back dismissal.
- Production title: **How do you want to share this post?**
- The reference omits “do”; use corrected copy.

## Options

1. **Share for everyone**
   - Teal selected radio by default when no prior choice exists.
   - Means an internal public reshare/repost with attribution.
2. **Save this post in private**
   - Neutral radio by default.
   - Means a current-user-only bookmark/save.

The entire row is tappable. The supplied reference has no Continue button, so tapping a row is the explicit command.

## Public share behavior

1. Validate the post is shareable/visible.
2. Prevent duplicate action for that post.
3. Submit with a reusable idempotency key.
4. On success, update `shareCount` exactly once and `isSharedByCurrentUser` when supported.
5. Close sheet and show concise success feedback.
6. Already-shared/idempotent response never creates duplicate reshares.

Public reshare preserves original author and canonical post reference. Never download/re-upload media to simulate sharing.

## Private save behavior

1. Save/bookmark for the current account only.
2. Update `isSavedPrivately` after success.
3. Close and show **Saved privately**.
4. Repeated saves are idempotent.

Private save never increments public share count, creates a feed post, or notifies the original author.

## Loading and failure

- Keep selected row visible with compact progress.
- Disable duplicate taps while mutating.
- Failure keeps sheet open, restores interaction, and shows Retry.
- Do not report success when server rejects.
- Deleted/private/blocked/non-shareable posts disable public share with reason while private save follows access policy.

## Backend contract

Current backend does not define public reshare/private-save endpoints or share count. Use typed repository boundaries and feature-gate until documented:

```dart
Future<SharePostResult> sharePostForEveryone(
  String postId, {
  required String idempotencyKey,
});

Future<SavedPostResult> savePostPrivately(String postId);
```

Define:

- Owner/visibility permissions.
- Attribution/canonical target.
- `share_count` and current-user states.
- Idempotency and unshare/unsave behavior.
- `post.shared` event for public shares only.
- Notification mapping; private saves produce no notification.

If **Share for everyone** is intended as external OS link sharing instead of internal reposting, revise the product label/contract explicitly; do not mix the two semantics.

## Accessibility

- Label modal, dismiss, title, options, selected/busy states, and errors.
- Minimum `44 × 44` rows.
- Do not rely on color alone for selection.
- Trap modal focus and restore it to the originating Share action.

## Architecture

```text
lib/modules/home/widgets/share/
  share_type_bottom_sheet.dart
  share_type_option.dart

lib/data/repositories/share_repository.dart
```

## Testing and acceptance criteria

- Matches `share type.png`: rounded sheet, handle, corrected title, two rows, trailing radios.
- Works from Poster, Video, and Job cards using exact post ID.
- Public share and private save never call the same operation accidentally.
- Public count updates once; private save never changes it.
- Loading, failure, retry, already-shared, already-saved, and non-shareable states work.

Deliver one safe, reusable bottom-up Share sheet for all media card types with distinct public-share and private-save semantics.
