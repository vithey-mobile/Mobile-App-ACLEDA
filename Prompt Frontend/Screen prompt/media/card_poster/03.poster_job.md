# 03 - Job Poster Card Prompt

Build the LinkedIn-style `JOB` poster card used in Home and Profile.

## Visual references

- `Prompt Frontend/screen image/home/job poster.png`.
- `Prompt Frontend/screen image/home/home screen.png`.
- Profile compact job list: `Prompt Frontend/screen image/profile/profile_job.png`.

## Typed input

```dart
JobFeedPost(
  id,
  author,
  content,
  mediaUrl,
  jobMeta,
  lifecycleState,
  applicationState,
  applicantCount,
  createdAt,
  reactionCount,
  commentCount,
  shareCount,
  userReacted,
)
```

Render only for `type == JOB`. Use structured job metadata; never infer job behavior from poster image/OCR/QR/caption keywords.

## Home card layout

1. Organization/author logo, name, relative time.
2. Right-side job action.
3. Structured headline, e.g. **Job announcement!** and short description.
4. Full-width hiring-poster image with preserved aspect ratio/`BoxFit.contain`.
5. Like, Comment, Share footer.

The AUB/AEON reference is fixture data only.

## Visitor application action

Map authoritative state:

| State | Action |
|---|---|
| Open, eligible, not applied | Teal **Apply** |
| Already applied | **Applied**; disabled or View Application |
| Closed/expired/full | **Closed** |
| Loading/checking | Stable compact spinner |

Apply opens `Routes.APPLY_CV` with canonical `jobPostId`, following `../../upload_cv/01.upload_cv.md`.

- Apply tap stops card/Post Detail navigation.
- Client state improves UX; career-service revalidates atomically.
- Never submit CV directly from poster image links/QR codes.

## Owner action

When `author.id == authUserId`:

- Never show Apply.
- Show **View Applicants** with count when supported, or owner management menu.
- Navigate to `Routes.JOB_APPLICANTS` with stable job ID.
- Optional Edit/Close/Delete only with documented contracts and confirmations.

## Profile compact variant

In Profile Jobs tab, compact card may show thumbnail, job title, organization, employment type, location, created time, state, and Apply/Applied/Closed or View Applicants based on owner/visitor.

Use the same `JobFeedPost`; do not maintain a second inconsistent job-state model.

## Media and metadata

- Preserve the uploaded job-poster image; do not crop readable hiring information.
- Application logic uses `jobMeta`: title, description, requirements, deadline, application limit/lifecycle, location/employment type when supported.
- QR code is visual content only and never bypasses Vithey application/security flows.
- Show image placeholder/error while retaining structured job details/action.

## Engagement

- Like toggles optimistically by post ID.
- Comment opens `../02.comment.md`.
- Share opens `../04.share.md`.
- Public share preserves original job attribution/state; private save is personal only.
- Actions stop card navigation.

## Required backend contract

The JOB feed response needs:

- Job post ID and author/organization summary.
- Job poster media URL; current JOB example must be extended with `media_file_id`.
- Structured `job_meta` including title/deadline and approved optional fields.
- Lifecycle `OPEN|CLOSED|EXPIRED|FULL`.
- Current-user `application_state`/`has_applied` without one request per card.
- Owner applicant count where authorized.
- Shared engagement counts/state.

Application limit/open-state must be enforced server-side. Missing state disables/hides unsafe Apply behavior rather than guessing.

## Errors and races

- Job closes between render and tap: Apply CV/server response changes card to Closed.
- `409` duplicate application reconciles to Applied.
- Missing/deleted job renders unavailable state.
- Unauthorized applicant list never leaks count/identities.
- Image failure does not remove structured job/action context.

## Accessibility

- Label organization, job title/state/deadline, poster image, Apply/Applied/Closed/View Applicants, and social actions.
- Do not communicate lifecycle/application state by color alone.
- Minimum `44 × 44` targets.
- Support long titles, large text, and `320 px` widths.

## Architecture

```text
lib/modules/home/widgets/
  job_poster_card.dart
  job_summary.dart
  job_action_button.dart
  job_poster_media.dart
```

One job-state mapper is shared by Home, Profile, Post Detail, and Apply CV result reconciliation.

## Testing and acceptance criteria

- Matches `job poster.png` hierarchy with uncropped hiring image.
- Dispatches only JOB data and uses structured job ID/meta.
- Visitor states map correctly; owner never sees Apply.
- Apply passes exact job ID and does not trigger Post Detail.
- Successful/duplicate application reconciles to Applied.
- Owner View Applicants is authorized and passes exact job ID.
- Comment/Share/Like actions remain isolated.
- Closed/race/image/error/long-text states do not overflow or allow invalid submission.
